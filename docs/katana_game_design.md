# 神前鍛刀對決 Katana Master（katana）遊戲設計

使用者指定（2026-10-20）：

* 在 PriTest 新增遊戲「神前鍛刀對決 katana master」。
* 基本模式幾乎完整模擬鍛刀：注意事項、要處理的步驟、可選的材料、刀的形狀等；做完拿出來評分。
* 基本模式後期可以多人鍛刀後「開刃試鋒」，多把刀互擊看誰殘留。
* **冶金學盡可能利用上，幾乎是精確的計算在背景跑**。
* 大部分選擇（鋼材、材料的初階階段）的預設結果是成品日本刀；另外也能做特別選擇：**非玉鋼的特殊材料做成日本刀**，或**玉鋼做成其他刃類武器**（闊劍、彎刀等）。

第二版（使用者指定，2026-10-20）：

* 開局可選 **表演模式** 或 **較真模式**（§1.1）。
* 各工序加上手作互動的小遊戲，「感覺真的在手敲鍛刀」（§2.1）。先做一版，之後再依個別工序調整。
* 非玉鋼打日本刀：**表演模式下不扣地鐵分**（屬於趣味）。
* 刀種擴充：知名武器與冷門但酷炫的武器（§4.1）。

## 1. 流程

1. **鍛刀（forge）**：13 道工序。同一裝置輪流，「每道工序全員各做一次」（`Core.currentForger`：進度最少者優先，同進度依座位）。換人時顯示交接畫面。
2. **神前審查（judge）**：地鐵／刃文（整體淬火的刀種改為「熱處理」）／姿／健全／研磨，各 20 分，共 100 分，等級：神品 ≥90、上上作 ≥78、上作 ≥65、良作 ≥50、普通作 ≥35、鈍刀。
3. **開刃試鋒（cut）**：五種目標（蓆一捲、三捲、青竹、五捲、鐵盔）依序，每人每目標一次刃筋時機小遊戲，可放棄目標。損傷（耐久）帶進互擊。
4. **對刀（clash）**：陀螺式圓形場地即時對刀，打到只剩一把（見 §7）。人數不足兩把時可加入對手刀（見習、村中鍛冶、神前奉納刀），也可從刀鞘拔刀參戰（AI 操作）。
5. **總結（end）**：總合 = 審查分 + 試斬分 × 2 + 互擊名次加分（15／8／4）。

### 1.1 模式（`state.mode`，複製到每把刀的 `blade.mode`）

| | 表演 `show`（設定畫面預設） | 較真 `serious` |
| --- | --- | --- |
| 加熱窗口 | 上下各放寬 40℃、偏離扣分減緩 1.5 倍；燒損門檻 +25℃ | 依冶金計算 |
| 瑕疵機率（膨脹、鍛裂、心鐵外露、熱脆、淬裂、刃切、調反開裂） | ×0.5（`Core.chance`） | 原值 |
| 小遊戲失誤 | 失誤量減半（`Core.skill`：0.6 → 0.8） | 原值 |
| 取出到入水的延遲 | 只算一半 | 全算（空冷 25℃/秒） |
| 非傳統材料打日本刀（現代鋼、大馬士革、烏茲） | 不扣分，只評語註明「趣味」 | 扣 3／2／1 |

冶金模型本身兩種模式相同，表演模式只是放寬容許範圍與機率。

### 2.1 各工序的小遊戲（第四版，使用者指定 2026-10-20／10-21：候選再加 20 種）

**每道工序有一組候選，每一局依 seed 抽一種**（`gameForSeed()`：同一局固定、重新整理不變；同一位鍛冶師連續兩道工序不抽同一種），所以每次鍛刀碰到的組合都不同。標題後面標出這次抽到的類型。

| 工序 | 候選 | 影響 |
| --- | --- | --- |
| 水壓・小割 | 碎裂（固定）→ 分揀板 | 敲擊精準度越低，斷口外觀與實際含碳的誤差越大（雜訊 0.06 → 0.26） |
| 積沸 | 堆疊 7 片 → 加熱（不變） | 堆疊整齊度：鍛接品質 ×(0.6+0.4·精準度) |
| 下鍛 | 加熱 → 節拍／圓弧／方向指令／連打／振り鎚／ふいご／回數打ち／拍子保持／火花（8／12 擊）；**有折返時再切半** | 夾雜物排出、晶粒、冷鋼敲擊 → 鍛裂；切半準確度併入打延成績 |
| 上鍛 | 加熱 → 節拍／圓弧／方向指令／連打／振り鎚／ふいご／回數打ち／狙い打ち／受け（8／12 擊）；**有折返時再切半** | 夾雜物排出、晶粒、冷鋼敲擊 → 鍛裂；切半準確度併入打延成績 |
| 造込 | 沸接加熱 → 圓弧／打ち分け／蓄力／照準／力加減／熱見比べ／色見／水平（6／8 擊） | 鍛接品質、心鐵外露風險 |
| 素延 | 圓弧／連打／蓄力／打ち分け／振り鎚／水平／受け／狙い打ち／火花（8／10 擊） | 均勻度、心鐵偏向 |
| 火造 | 記憶敲打／打ち分け／方向指令／照準／順打ち／疵探し／型／色見／熱見比べ | 打不準 → 身幅 ±3mm×誤差、重 ±12%×誤差、彎度偏離；姿最多 −3 |

**各玩法**

| 玩法 | 操作 | 判定 |
| --- | --- | --- |
| 碎裂 | 敲鋼餅上的弱點（會縮小、沒敲到就換位置），裂痕逐次擴大，敲滿後碎成 12 片散在桌上；分揀板點一片放大看斷口再分類 | 距離弱點中心越近越好 |
| 圓弧判定 | 指針繞圈，判定格在隨機位置出現，指針進格時按（空白鍵・按鈕・點圓盤） | 白心 1.0、金格 0.6〜1.0、格外／錯過 0 |
| 節拍 | 音符落到線上時按對應軌道（3 軌 F J K：小鎚・先手左右；4 軌 D F J K：刃・鎬・地・切先），樂譜隨機 | 良 1.0／佳 0.8／可 0.5／失 0（窗 ±50・95・150ms 較真，±70・120・180ms 表演） |
| 記憶敲打 | 看位置亮起的順序再依序敲（火造：刀身 8 點；切銘：每字左右兩個鏨位） | 正確敲數／總數；敲錯該輪剩下都算錯 |

| 打ち分け | 刀身 7 個位置隨機亮起熱點、慢慢熄滅，熄滅前點掉 | 0.6＋0.4×剩餘時間比例；熄滅 0 |
| 方向指令 | 照亮起的箭頭按方向（方向鍵・WASD・按鈕；各方向代表棟／刃／元／先等部位） | 0.6＋0.4×剩餘時間；按錯或超時 0 |

| 振り鎚 | 大鎚像擺錘來回，擺到最低點時按 | 偏離角度：半寬 11°（較真 7°）內 0.6〜1.0，兩倍半寬外 0；擺 2.6 次沒按 0 |

| 間合い | 按住到指定秒數再放開，量表在 60%（較真 30%）處消失 | 時間差半寬 110ms（較真 70ms） |
| 火花 | 等火花迸出時按；較真有假閃光 | 0.6＋0.4×剩餘時間（650／480ms）；太早 0 |
| 狙い打ち | 游標沿李薩如曲線移動，經過記號時按 | 距離半寬 12px（較真 8px） |
| 砥石滑らし | 按住時力道來回擺動，放開推出砥石，有摩擦停下（表演顯示預測落點） | 停點與目標距離半寬 14px（較真 9px） |
| 拍子保持 | 前 4 拍有節拍器，之後消失，照拍子繼續敲 | 每拍時間差半寬 75ms（較真 50ms）；漏拍 0 |

| 順打ち | 照一、二、三…順序點（5／7 個） | (1−0.15×點錯數)×(0.7＋0.3×剩餘時間)；超時＝完成比例×0.5 |
| 型 | 整串方向一次顯示，限時依序輸入 | 0.7＋0.3×剩餘時間；按錯或超時＝完成比例×0.5 |
| 受け | ←／→或拖曳移動火箸接住落下的鋼片 | 落點與火箸距離半寬 22px（較真 15px） |

* 小遊戲只交給核心同樣的成績欄位（`acc`，敲打類另有 `strikes`／`cold`／`reheats`），冶金規則與數值計算不變；切半是併入交給核心的打延成績。下鍛・上鍛與素延仍需至少 `HAMMER_STRIKES = 8` 擊。
* 難度依鍛刀模式：表演短而寬鬆、較真長而嚴格（`PriTestKatanaGames.DIFF`／`MORE`；第四批的數值寫在 `katana_games2.js` 各玩法的 `a.k(表演, 較真)`）。
* 第四批 20 種（`katana_games2.js`）共用一個畫布框架 `make(type, spec)`：計時類用輸入事件的 `timeStamp` 判定；鋼只在回合進行中冷卻（要想的玩法冷得較慢，`coolRate`），回合之間冷到 1000℃ 以下自動回爐；持續類（ふいご・水平・力加減・刃文なぞり）長度不超過冷卻時間 60%，回報的擊數＝工序要求的擊數。
* 鋼的冷卻：好好玩不會冷打——節拍依冷卻時間切樂句、樂句間回爐；記憶敲打輪到敲才取出；連打的長度不超過冷卻時間 60%；打ち分け・方向指令打完一半、蓄力每 4 擊自動回爐；圓弧判定打得慢要自己按「回爐」。
* 測試：每個遊戲框有 `ktAuto(quality)` 依規則自動操作。`games_check.js` 逐一檢查 29 種玩法（兩種模式、好壞兩種打法；`ONLY=pendulum,color` 可只跑指定的）與抽選（固定、不連續重複、60 局的組合多樣、每種都抽得到）；`ui_check.js` 打完整局。

## 3. 冶金模型（`katana_core.js`）

全部以文獻上的經驗式或物理式計算，**只有標明「校正值」的常數是依實務結果調整**。

| 現象 | 模型 |
| --- | --- |
| 脫碳 | 碳在沃斯田鐵中的擴散係數 `D = 2.3e-5·exp(−148 kJ/RT)`；每次加熱的脫碳比例 `4/h·√(Dt/π)·保護倍率`（鋼坯 15mm、每次 100 秒、每折 3 次加熱、灰泥保護 0.55）。 |
| 氧化損失 | 拋物線氧化，`exp(−Q/2RT)`、Q = 165 kJ；以「1300℃、有保護時每次 2.7%」校正。 |
| 沸燒上限 | Fe–C 固相線（1538℃ → 0.17% 1495℃ → 2.11% 1148℃ 的二次近似，Ni 每 1% −3℃）。鍛接窗口＝固相線 −150〜−35℃，超過固相線 −15℃ 即燒損。 |
| 層間均質化 | 折返後層厚 λ = 15mm／層數，與擴散距離比較，碳的不均（consistency）指數收斂。 |
| 熱脆 | S > 0.012% 且 Mn/S < 4 時，在 950〜1150℃ 鍛打會因 FeS 晶界熔化而開裂。 |
| 變態點 | Andrews：`Ac1 = 723 − 10.7Mn − 16.9Ni + 29.1Si + 16.9Cr + 6.38W`；`Ac3 = 910 − 203√C − 15.2Ni + 44.7Si + 104V + 31.5Mo + 13.1W`；Acm 依 ES 線（每 1%C 約 314℃）。 |
| 淬火適溫 | 亞共析：Ac3 + 20〜60℃；過共析：Ac1 + 20〜60℃。 |
| 沃斯田鐵化 | 低於 Ac1 不淬硬；亞共析在 Ac1〜Ac3 之間依槓桿定則殘留肥粒鐵（焼きむら）；過共析的溶入碳量隨溫度沿 Acm 線增加，其餘為未溶碳化物。 |
| 淬透性 | Grossmann 理想臨界直徑 `DI = 0.29√C × 晶粒度係數 1.09^(7−G) × Π(1 + k·合金)`（Mn 3.333、Si 0.7、Ni 0.363、Cr 2.16、Mo 3.0、W 0.5、V 1.73）。臨界直徑 `Dc = DI·H/(H+0.8)`。 |
| 淬火強烈度 H | 鹽水 1.9、冷水 1.25、溫水 0.95、熱水 0.6、油 0.3。土層倍率：薄 ×1.5（破壞蒸氣膜、加速冷卻）、中 ×0.6、厚 ×0.25。 |
| 截面 | 刃口厚 1.2mm，往鎬（或雙刃的中脊）線性增厚到「重」。楔形斷面以 1.2t 為等效圓棒直徑。截面取 21 點計算。 |
| 麻田散鐵 | 冷卻分率 `1/(1+exp((1.2t − Dc)/(0.2Dc)))` × Koistinen–Marburger `1 − exp(−0.011(Ms − 浴溫))`；Ms 由 Andrews `539 − 423C − 30.4Mn − 17.7Ni − 12.1Cr − 7.5Mo − 7.5Si`。其餘為殘留沃斯田鐵與波來鐵。 |
| 硬度 | 麻田散鐵：Hodge–Orehoski 多項式；各相以 HV 線性混合再換回 HRC；未溶碳化物最多 +3。 |
| 刃文 | 硬化邊界＝由刃口往內第一個麻田散鐵 < 50% 的位置。清晰度＝（麻田散鐵 75%→25% 的過渡寬度越窄越好）×（邊界與土線吻合度）×（1 − 刀背麻田散鐵／刃口麻田散鐵）。 |
| 淬火反り | 麻田散鐵變態膨脹 `ΔV/V ≈ 1.68·C %` 作為固有應變，以樑理論求曲率 `κ = Σε(y−yc)t / Σ(y−yc)²t`，弓高 `κL²/8`。再乘**塑性放大 2.5（校正值**：淬火初期刃先收縮、高溫刀背降伏，彈性解只有實際約四成；依「淬火約產生 1〜1.5cm 反り」校正）。雙刃對稱 → 0。 |
| 晶粒 | 鍛打再結晶 6 + 精準度×1.2（沸燒過高變粗）；正常化 1/2/3 次 +1.2/+1.8/+2.1；淬火過熱每 35℃ −1；過共析有未溶碳化物時 +0.5。 |
| 淬裂 | `0.018 × H^1.6 × (Cd/0.6)² × 粗晶 × 低 Ms × 刃文種類 × 刀背也淬硬 ×1.5 × 既有瑕疵 × (1+5P)`。 |
| 回火 | 溫度來自回火色小遊戲（數值）。Hollomon–Jaffe `P = T(K)(20 + log t)`；P > 8200 起每 1 降 0.003 HRC（P > 11500 後 0.0018）。230℃ 以上殘留沃斯田鐵分解。 |
| 韌性 | `110 − 1.5HRC + 回火恢復 − 回火麻田散鐵脆性（230〜400℃，谷底約 315℃）+ 3(G−7) − 18(Cd−0.6) − 10RA − 0.35鐵滓 − 150P + 3Ni + 刀背未淬硬加成`，再與心鐵（低碳肥粒鐵）依造込的心鐵比例複合。 |

這些是有文獻依據的近似，不是有限元素模擬；刀匠實務仍有許多無法量化的因素。

### 3.1 會自然出現的現象（測試有覆蓋）

* 玉鋼幾乎不含 Mn/Si，淬透極淺 → 刃文由土層控制、刀背不硬；但寬幅刃文（丁子、皆燒）要硬化到土線需要更急的淬火（鹽水），淬裂風險隨之上升。
* 1060（Mn 0.75）、青紙（Cr・W）淬透深 → 厚土下也局部淬硬，刃文糊掉、刀背變硬。
* 過共析鋼加熱過頭 → 溶入碳增加、Ms 下降、殘留沃斯田鐵增加、晶粒粗化、淬裂風險升高。
* 雙刃劍兩側對稱 → 淬火不產生反；彎刀的深彎、廓爾喀刀的內彎要靠火造。
* 烏茲鋼超過 Acm 或折返 → 碳化物溶解，紋路消失；S 多、Mn/S 低 → 熱脆。
* 鍛太多次 → 脫碳到淬不硬；不撒灰泥 → 脫碳、氧化都變多。

## 5. 審查

* **地鐵**：鐵滓 7、含碳是否在範圍 4（烏茲鋼範圍 1.2〜1.8%），再依紋路系統加分：
  * 地肌（玉鋼系）：地肌美觀 3〜4 ＋ 均質度 2 ＋ 卸鐵 1；折返 > 18 次 −3、< 10 次 −2。
  * 無紋（現代鋼）：日本刀 +1（並評「看不到地肌」），異國刀劍 +4。
  * 大馬士革：層數接近 200 層最佳（最多 +5）；做成日本刀 −2。
  * 烏茲：紋路保留 +6；做成日本刀 −1。
  * 流星刀：3.5 + 傳說 1 + 均質度。
  * 日本刀用非傳統和鋼：較真模式 −3（神前視為偏離正統）；表演模式不扣分（趣味）。大馬士革、烏茲做成日本刀的 −2／−1 也只在較真模式。
* **刃文**（差異淬火刀種）：`刃文潛力 × (0.4 + 0.6·清晰度) × (0.4 + 0.6·硬度符合度) + 足 0.5`；未置土僅依硬度給最多 6。
* **熱處理**（整體淬火刀種）：`14·硬度符合度 + 6·刃背均勻度`。
* **姿**：刃長、彎度、身幅、重是否在該刀種範圍，斷面／切先／反的位置是否合該刀種。
* **健全**：20 − 各瑕疵扣分。
* **研磨**：研磨分 × 14 ＋ 刃肉 1 ＋ 莖 2 ＋ 有銘 3。

## 6. 試斬

沿用 `stats()` 算出的硬度、韌性、鋒利、重量、耐久。試斬：`鋒利 × (0.55 + 0.45·刃筋) + 重量 × 8 ± 8 ≥ 目標難度` 即斬斷；硬脆的刀打硬目標易刃崩、軟的刀易彎，有淬裂的刀砍鐵盔可能折斷。

### 7.3 對刀場（`static_src/katana_arena.js`，`window.PriTestKatanaArena`）

固定步長 1/60 秒的確定性模擬（種子＋玩家放牌時間點決定結果）。場地半徑 100，碗形重力 `a = −0.32·r`、摩擦 0.55/秒。

* **刀 → 陀螺參數**（`profile(snap)`）：耐久＝`stats().integrity`；攻擊 `0.5 + 鋒利/100 + max(0, HRC−55)/40`；防禦 `0.6 + 韌性/100 + max(0, HRC−50)/100`；觸及半徑 `8 + 刃長/7`；推進力 `30·打法倍率 / 質量^0.35`。
* **打法**：質量 < 0.75 持久型；韌性 ≥ 鋒利+10 或質量 ≥ 1.6 防禦型；鋒利 ≥ 韌性+8 攻擊型；其餘均衡型。影響推進力、勢い衰減與追擊力。
* **特性**：雙刃（分開時補一刀）、拖斬（反り ≥ 20：僵持 ×0.7、傷 ×1.2）、刺擊（直的細雙刃：撞擊傷 ×1.5）、重擊（≥ 1.5kg：彈飛 ×1.5）、波刃（多削勢い）、硬而脆（HRC ≥ 61：崩刃）、偏軟（HRC < 52：彎曲變慢）、帶淬裂（相接時 5% 折斷）。
* **碰撞**：圓相交且相對法向速度 ≥ 9 →「刀刃相接」：鎖住 0.8〜2.3 秒，兩把刀刀尖相抵繞中點旋轉、持續噴火花，每秒互削 `6.5·攻/防` 耐久與勢い，往較弱的一方推；結束時依推力差彈開，該對冷卻 0.7 秒。速度不足只是擦撞彈開。撞擊瞬間另有 `相對速度·0.045·攻/防` 的傷。
* **退場**：耐久 0＝折斷；勢い 0＝力竭（自然衰減約 90 秒、相接與撞牆會加速）。剩一把即結束；15 回合（60 秒）到時以 `耐久比·0.7 + 勢い·0.3` 判定。
* **招式卡**：牌庫＝基本 13 張（踏進×2、守勢×2、調息×2、看破、一閃、居合、楓葉斬、開花斬、落櫻斬、吹雪斬）＋打法追加 2 張，手牌 3 張、等待區 2 格。放進等待區後在 `目前回合 + 1 + wait` 的回合交界發動（踏進／守勢／調息／看破 wait 0，一閃／居合／楓葉斬 wait 1，覺醒招式 wait 2 且每場一次）。回合交界補牌。AI：每回合 55% 機率出牌，耐久 < 70% 或第 4 回合後優先放覺醒招式。
* 鍛刀局內的對刀：試斬剩下的耐久帶入；結果（`placing`）沿用總結的名次加分（15／8／4，只算玩家）。對刀場狀態放在 `ui`，不存檔（重新整理會重打）。

### 7.4 刀鞘與邀請

* `localStorage["pritest-katana-scabbard"] = { v: 1, swords: [{ uid, snap, guest, rec: { w, l }, saved }] }`，**最多 50 把**（使用者指定 2026-10-20，原 60）。滿了時「收入刀鞘」與「收下客刀」會擋下並提示，不會悄悄刪掉舊刀；匯入時放不下的刀會回報略過幾把。`snap` 是 `Core.swordSnapshot()`：畫圖與戰鬥需要的欄位＋`stats()`＋覺醒招式。
* **uid**：新收入的刀是 `"k" + 32 位 hex 亂數`，第一次收入時記在刀身 `blade.scUid`（`bladeScUid()`）；舊資料的 `"seed|玩家id"` 照常沿用。快照帶 `snap.uid`（原主 uid），邀請碼與匯出都會帶著走；收下的客刀 uid＝`"guest|<原主 uid>"`（舊版邀請碼沒有 uid 時退回 `"guest|" + hashStr(快照)`）。同一把刀不管經過幾台裝置都認得出來，重複收下不會變兩把。
* **邀請網址**：`katana/index.html?duel=<base64url(JSON(snap))>`。對方打開後在準備畫面最上方看到客刀，預設以自己刀鞘的第一把刀迎戰（沒有就用村中鍛冶之刀），對刀在對方裝置上進行；客刀可由 AI 或對方操作，也能收進刀鞘（`guest`）。收到的碼一律經 `sanitizeSnap()` 只留已知欄位、數值夾在合法範圍。
* 也可以在準備畫面貼上邀請網址／刀碼加入對刀；自由對刀可選刀鞘的刀、客刀、對手刀，各自指定玩家或 AI。戰績寫回刀鞘。
* **整個刀鞘的匯出／匯入**（換裝置用）：檔案 `{ kind: "pritest-katana-scabbard", v: 1, exported, swords: [...] }`（下載 `.json`），或刀鞘碼 `"KTSC1." + base64url(同一份 JSON)`。匯入時每把刀都過 `sanitizeSnap()`、uid 須符合 `/^[A-Za-z0-9|_.:-]{1,100}$/`。
  * **合併**：同 uid 取 `saved` 較新的快照、勝／敗各取較大值；新刀加入；最後依 `saved` 新→舊排序。
  * **覆蓋**：確認一次後整個取代。

### 7.5 連線對刀（使用者指定 2026-10-20，最多 8 把刀）

* 準備畫面「連線對刀」→「建立房間」，網址變成 `katana/index.html?room=<g+32hex>`，傳給其他人；其他人打開網址或貼上網址加入。各自從**自己的刀鞘**選刀、按「準備好了」；沒選刀＝觀戰。房主可加入 AI 對手刀補人數。出戰總數（玩家＋AI）上限 8 把，滿了之後新加入的人只能觀戰。
* 模組：`katana_net.js`（`PriTestKatanaNet`）負責房間協定與同步；畫面在 `katana.js`。Firebase 沿用 `game_storage.js` 的 `rtSet`／`rtSubscribe`／`rtTransaction`／`rtSetWithOnDisconnect`，資料放在 `games/<roomId>/rtState/kt/...`，**`database.rules.json` 不用改**。Firebase SDK 只在開房／進房時才載入。
* 資料：`meta { host, no, status: "lobby"|"play" }`、`on/<cid>`（在線，onDisconnect 自動移除）、`pl/<cid> { name, snap, ready, at }`、`npc`、`m/<no> { seed, fighters, startAt }`、`in<no>/<r>/<cid>`（各玩家第 r 回合放的牌）、`s<no> { r, st, end, seq }`（房主在回合交界寫的整份狀態）。
* **同步方式（房主為準）**：大家用同一個 seed 各自模擬（固定步長）。招式只在回合交界發動，所以玩家放的牌先記成「下個交界生效」；交界前 0.25 秒起放的牌算下一回合。到交界時房主收齊在線玩家的牌（最多等 1.5 秒），用 `Arena.queueCard` 套用後把 `Arena.serialize(a)` 寫進 `s<no>`；其他人停在交界，收到後 `Arena.restore()` 換上再繼續。每回合重新對齊，不同瀏覽器的浮點誤差不會累積；落後的人收到較新的狀態會直接跳上去。結束也以房主送出的結束狀態為準。
* 為此 `katana_arena.js` 的亂數改成存在 `a.rng` 的數字（同一個 mulberry32，結果與舊版完全相同），並提供 `serialize`／`restore`（binds 的 fighter 參照換成 id）／`atBoundary`。
* 斷線：玩家離線→房主在下一個交界把那把刀改成 AI（`f.human = false`，寫進狀態，大家看到一致）；房主在大廳離線→最早加入的在線者自動接手（transaction）；房主在對局中離線→對局中止。對局中途進房或重新整理的人以觀戰者身分從最新狀態接著看。
* 戰績：每個人只把自己出戰那把刀的勝敗寫回自己的刀鞘。

### 7.6 試合模式（使用者指定 2026-10-20）

對刀場有兩種模式（`Arena.create({ mode })`）：**陀螺**（`koma`，預設，§7 的自轉滑行）與**試合**（`shiai`）。自由對刀、對刀實驗場、連線對刀（房主選，存在 `kt/mode`、對局 `m/<no>.mode`）可以切換；鍛刀局內的互擊維持陀螺。

* 刀不自轉，像握在手上。每把刀是一個狀態機（`f.sh.st`）：
  1. **收刀** `sheathe`（0.45〜1.05 秒）：停在壁面，刀身畫短。
  2. **刀光** `aim`（0.55 秒；踏進・一閃時減半）：抽出斬擊方向，畫出到對面壁面的刀光路徑（虛線，逐漸變亮）。
  3. **斬擊** `slash`：沿路徑直線前進，碰到壁面就停下回到收刀。速度＝175 ×（推進力／30）× 勢い（0.6＋0.4×勢い）× 加速類增益。
  4. **彈開** `recoil`：相接或被擊退後往隨機方向滑行、減速，停下（或碰到壁面）回到收刀。
* 斬擊方向：55% 大致朝最近的對手（±25° 隨機），其餘從壁面往場內隨機。踏進・一閃・覺醒招式發動中（`noSeek` 除外）直接斬向對手。純隨機的話兩把刀很少相遇，所以保留這個偏向。
* **碰到就是刀刃相接**（不論對方在斬擊中或停在壁面）：火花、雙方同時互相削耐久，損傷＝9 × 攻／防 × 損傷倍率 × `bindMul` × 相對速度係數（0.6〜1.5）× √(質量比)（反り刀 ×1.15、楓葉斬 ×1.6、刺突在斬擊中 ×1.4），並削對方勢い；崩刃・燒割・彎曲照舊。一閃・燕返等「不陷入僵持」的接觸只打招式本身的傷，不互削。之後雙方大致往遠離對方的方向（±69° 隨機）彈開；重的刀把對方彈得更遠。
* 雙方損傷先算好再同時套用（否則編號小的一方永遠先出手）；同時折斷時以造成損傷較多者勝，再相同就抽籤。
* 招式全自動：玩家的刀也由 AI 在回合交界出牌；連線時房主不必等玩家的牌。勢い不會自然衰減、沒有力竭出局（下限 0.2），只影響斬擊速度。
* 實測（每組 100 場）：1 對 1 約 14〜23 秒、相接 4〜7 次；8 把約 17 秒、相接約 37 次。

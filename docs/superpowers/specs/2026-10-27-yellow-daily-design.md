# 黃牌：每日挑戰設計（2026-10-27）

## 目的

提高重玩性：每天一局，所有人當天玩同一局，可以比較結果。
這是「增加多樣性」四個子專案的最後一個（詞綴 → 戰場狀態 → 雙人連攜卡 → **每日挑戰**）。

## 使用者選定（2026-10-27）

- 原始想法：固定 seed，再加上隨機抽兩三個苦痛修正。
- 英雄：**當天固定英雄**。依日期決定 4 位英雄，玩家只選人數（n 人取前 n 位），同人數的人玩到的是完全同一局。
- 比較方式：**本機紀錄＋分享文字**。不動伺服器、不改 Firebase 規則。

## 規則

- 日期：裝置的當地日期 `YYYY-MM-DD`。
- `Core.dailySetup(date)`：以 FNV-1a 雜湊 `"yellow-daily-" + date` 當亂數種子：
  - 4 位不重複的英雄（全部 19 位中洗牌取前 4）；
  - 2～3 個苦痛修正（`D.TMODS` 洗牌取前 2～3 個，強度 1～2，`left = DAILY_LEFT (999)`＝整局有效）；
  - 對局 seed＝雜湊 `"yellow-daily-seed-" + date`。
- `Core.createDaily(date, n)`：座位順序同一般開局（0、3、1、2）；英雄卡牌全解鎖（`lv` 不帶＝99）、不帶出發遺物、苦痛等級 0、不是無盡模式；`st.daily = date`。
- 同一天同人數的開局狀態完全相同（JSON 相同）。之後的分岔只來自玩家的選擇。
- 成績：`st.turns`（整局累計回合數）。`dailyBetter(a, b)`：通關＞推進得遠（幕 × 層）；一樣時回合少的好。

## 紀錄與分享

- `localStorage["pritest-yellow-daily"] = { 日期: { 人數: { win, act, floor, turns } } }`，只留最近 14 天。
- 結束畫面記錄一次（`st.dailyDone`，重新整理不會重複記），新紀錄時顯示「今日新紀錄」。
- 分享文字：標題（日期、人數）、英雄、今日修正、結果、遊戲網址；「複製」按鈕（`navigator.clipboard`，失敗時用 `execCommand("copy")`）。

## 畫面

- 入口最上面的「📅 每日挑戰 日期」面板：說明、今日修正、人數 1～4、今日英雄（點了顯示英雄說明）、今日最佳（這個人數）、開始按鈕。
- 戰鬥中上方列「📅 每日 日期」標籤；整局有效的修正在提示裡寫「整局有效（每日挑戰）」，不顯示剩餘層數。
- 存檔沿用本機存檔，可以中途繼續。
- 三種語言。

## 測試與驗證

1. `core_check.js`：同一天設定相同、4 位不重複英雄、2～3 個修正、不同天大多不同、同一天同人數開局完全相同、英雄取前 n 位、全解鎖無遺物、修正整局有效、回合數累計、成績比較。
2. 臨時 Playwright：入口面板、換人數、開始後的標籤與英雄、結束畫面的紀錄／分享文字／複製、回到入口顯示今日最佳、手機寬度、日文英文沒有漏翻、沒有 JS 錯誤。

## 不做的事

- 連線房間的每日挑戰。

# 東正小遊戲（toushou）內線模式 設計規格

日期：2026-10-21
狀態：使用者已確認流程與數值方向，待審閱本文件
前置：

## 1. 目標

新增第二種遊戲模式「內線模式」，與現行玩法（以下稱「經典模式」）並存，開局時二選一。

延續「簡介＝滿分說明、消息往下砸」的概念：每個標的有一個只有內線人知道的**實價 T**，
內線人用消息暗示 T，其他人解讀後預測 T。彩池獎勵**解讀得準**的人，內線人則依**傳達得準不準**拿獎金或賠錢。

經典模式的規則、存檔與測試完全不變。

## 2. 開局設定

| 設定 | 說明 | 預設 |
| --- | --- | --- |
| `mode` | `classic`（經典）／`insider`（內線） | `classic` |

選 `insider` 時，以下設定**隱藏且不生效**（都依賴股價變動，內線模式沒有）：
風向卡、黑天鵝、板塊連動、加減分方式（主持人／投票）、每票上限、任務卡。

仍然有效：玩家人數、初始籌碼、標的數量與類別、最低押注、連線模式。

舊存檔缺少 `config.mode` 時視為 `classic`。

## 3. 一個標的的流程

| 步驟 | 階段 `phase` | 內容 | 誰操作 |
| --- | --- | --- | --- |
| 1 | `reveal_target` | 公開標的（名稱、類別、簡介、特徵、切入點）與本標的的內線人。主持人按「開始」時系統秘密抽 T | 主持人 |
| 2 | `insider_stake` | 內線人**只看標的、不看 T**，依把握度輸入「傳達押金」 | 內線人 |
| 3 | `insider_narrate` | 內線人查看 T（遮蔽畫面，只有內線人看得到） | 內線人 |
| 4 | `insider_narrate` | 內線人釋放 1～3 則消息，可以出牌、改寫或自訂，之後按「敘述結束」 | 內線人 |
| 5 | `bet` | 其他人秘密押注：押注額＋預測 T | 內線人以外有籌碼的玩家 |
| 6 | `discuss` | 全員下注完成，自由討論；主持人按「公布答案」 | 主持人 |
| 7 | `settle` | 公布 T，分配彩池，結算內線人 | — |

### 3.1 實價 T

- **0～99 的整數，平均抽取**（不會出現 100）。用 state 內的 PRNG，各裝置結果一致。
- 進入 `insider_stake` 時就已決定並存進 state。內線人在步驟 3 之前，畫面上不顯示 T。

### 3.2 內線人輪替

- 開局時用 PRNG 抽 `insiderOffset`（0～人數−1）。
- 第 k 個標的（k 從 0 起算）的內線人＝座位 `(k + insiderOffset) mod 人數` 的玩家。
- 標的數是人數的整數倍時，每人當內線人的次數相同。設定畫面在不整除時顯示提示：「標的數不是人數的倍數，內線人次數會不平均」。

### 3.3 傳達押金（步驟 2）

- 整數，0 ≤ 押金 ≤ floor(目前籌碼 × 50%)。籌碼為 0 時只能押 0。
- 押 0 代表放棄：不賺也不賠。
- 確定時從內線人的籌碼扣除，暫存在 `current.insiderStake`，**不放進彩池**。
- 押金在步驟 2 確定後即**公開**（2026-10-21 使用者確認）：押金大小是「我有多大把握」的訊號，供其他人判斷。

### 3.4 內線人敘述（步驟 4）

- 沿用經典模式的 `releaseNews`：直接打出手牌、手牌改寫、純自訂三種方式；用到手牌就補 1 張。可直接打出的條件同經典模式 §7.3。
- 至少 1 則、最多 3 則。第 3 則送出後自動結束，也可以在第 1、2 則之後按「敘述結束」。
- **不能直接說數字或明示分數**（例如「大概 60 分」）。程式無法判斷，只在畫面上顯示規則提示，由玩家自律。
- 消息累積在標的消息面，**沒有加減分、沒有股價變化**。

### 3.5 其他人押注（步驟 5）

- 下注者＝內線人以外、籌碼 > 0 的玩家。不限順序，可同時下注（同多裝置規格）。
- 押注額規則同經典模式（≥ 最低押注且 ≤ 籌碼；不足最低押注時只能全押）。
- 預測 T：0～99 的整數。
- 下注者為 0 人（其他人都沒籌碼）時，跳過步驟 5、6，直接進入結算。

### 3.6 討論（步驟 6）

- 預測內容在公布答案前**不公開**，只顯示「已下注 x / n」與押注完成狀態。
- 主持人按「公布答案」進入結算。

## 4. 結算

### 4.1 彩池

- 呼叫經典模式的 `settleTarget(bets, T, seatOrder)`：依 |預測 − T| 排名，按 100％／70・30％／60・30・10％ 分配，並列與零頭規則不變。

### 4.2 內線人

誤差 E＝其他人預測的均方根誤差：

```
E = √( Σ (預測ᵢ − T)² / 下注人數 )
```

（不用「標準差」：標準差只量預測彼此多集中，大家一起猜錯時也會是 0。）

| 條件 | 結果（押金記為 S） | 內線人淨損益 |
| --- | --- | --- |
| E ≤ 10 | 拿回 S＋S | ＋S |
| 10 < E ≤ 20 | 拿回 S＋floor(S × 0.5) | ＋floor(S/2) |
| 20 < E ≤ 30 | 拿回 S | 0 |
| 30 < E ≤ 40 | 拿回 S − floor(S × 0.5) | −floor(S/2) |
| E > 40 | 不拿回 S，另外再付 floor(S × 0.5) | −S − floor(S/2)（賠超過押金） |

- 比較時用整數運算，不取根號：`Σ(預測ᵢ − T)² ≤ 100 × 下注人數` 等同 E ≤ 10，以此類推。
- 下注人數為 0 時無法計算 E：原數退回押金，標示「無人下注」。
- 押金上限是籌碼的 50%，所以「再付 S/2」時籌碼一定夠付，不會變成負數。
- 獎金與罰金由**銀行**支付／收取，內線模式全場籌碼總數不守恆（同經典模式的「紓困加碼」）。

### 4.3 結算畫面

公開：T、內線人押金、E（顯示到小數第 1 位）、內線人結果，以及每人的押注／預測／誤差／名次／取回／盈虧。

## 5. 整局結算

最終分數＝籌碼（內線模式沒有任務卡），依此排名。每個標的的回顧列出：內線人、T、E、內線人損益、消息面。

## 6. 規則引擎修改（`toushou_core.js`）

- `config.mode`；`newGame` 在 `insider` 時：
  - 抽 `s.insiderOffset`。
  - 不建立風向牌堆和黑天鵝牌堆，也不發任務卡，以免消耗 PRNG。經典模式的亂數序列不變。
- 新增 `insiderFor(s, targetIndex)`。
- `reveal_target` 的 `startBetting` 依 mode 分流；內線模式改呼叫 `startInsider(s)`：抽 T，建立 `current`，進入 `insider_stake`。
- 新增 action：

| action | 階段 | 說明 |
| --- | --- | --- |
| `{ type: "insiderStake", playerId, amount }` | `insider_stake` | 只有內線人；檢查範圍；扣籌碼 → `insider_narrate` |
| `releaseNews`（沿用） | `insider_narrate` | 只有內線人；不進入 `vote`，記入 `current.news`；滿 3 則自動進入 `bet` |
| `{ type: "endNarration", playerId }` | `insider_narrate` | 只有內線人；至少已有 1 則 → `bet`（無下注者時直接結算） |
| `placeBet`（沿用） | `bet` | 內線模式下 `predict` 限 0～99；全員下注完成 → `discuss` |
| `{ type: "revealAnswer" }` | `discuss` | → 結算 → `settle` |

- 新增純函式 `insiderResult(bets, truth, stake)` → `{ count, sumSq, error, tier, net }`。
- `current`（內線模式）：`{ insiderId, truth, insiderStake, bettors, bets, pot, news }`。
- `history[i]`（內線模式）新增：`mode: "insider"`、`insiderId`、`truth`、`insiderStake`、`insiderError`、`insiderNet`；`finalPrice` 填 T，讓共用的回顧畫面可以直接顯示。
- 新增錯誤 key：`ts_err_not_insider`、`ts_err_stake_range`、`ts_err_need_news`、`ts_err_predict_range`。

## 7. UI 修改（`toushou.js`）

- 設定：模式選擇；`insider` 時隱藏 §2 所列欄位，並顯示不整除提示。
- 標的卡：顯示「本標的內線人：○○」。
- `insider_stake`：內線人的遮蔽畫面＋押金輸入（顯示上限）；其他裝置顯示「等待內線人押金」。
- `insider_narrate`：內線人的遮蔽畫面中**大字顯示 T**＋手牌＋消息輸入＋「敘述結束」；顯示「不能直接說數字」提示。其他裝置看到逐則累積的消息面。
- `bet`：同經典模式的下注畫面，預測欄位範圍 0～99，預設值 50。
- `discuss`：顯示「已下注 x / n」；主持人有「公布答案」按鈕。
- 連線模式：T 只在擁有內線人座位的裝置顯示。雲端資料可以被開發者工具讀到，與現行秘密資訊相同，派對遊戲可接受。

## 10. 驗證

1. `tools/toushou_check/core_check.js` 新增：
   - T 範圍為 0～99，同 seed 結果相同。
   - 內線人輪替：人數 3、標的 6 時每人剛好 2 次。
   - 押金範圍（含籌碼 0、奇數籌碼的 floor）。
   - 敘述 0 則不能結束、滿 3 則自動結束、純自訂不消耗手牌。
   - 內線人不能下注、預測 > 99 被拒。
   - E 的五個區間邊界（E 恰為 10／20／30／40）。
   - 賠超過押金時籌碼不為負。
   - 無下注者時退回押金。
   - 彩池分配沿用並守恆。
   - 經典模式既有檢查全部維持通過；舊存檔無 `mode` 時為經典。
2. `tools/toushou_check/ui_check.js`（經典模式）維持通過；內線模式另寫 `tools/toushou_check/insider_ui_check.js`
   （單機 3 人 × 3 標的），驗證 T 只在內線人遮蔽畫面出現、押金公開、輪替、重新整理還原。
3. 多裝置：T 只在擁有內線人座位的裝置繪出（UI 端判斷 `owns()`）。`multi_device_check.js` 尚未加內線模式的一局（需 Firebase Emulator），之後補。

## 1. 開局設定

| 設定 | 說明 | 預設 |
| --- | --- | --- |
| `blackSwanEnabled` | 啟用黑天鵝事件卡 | 關 |
| `sectorLinkEnabled` | 啟用板塊連動 | 關 |

兩者互相獨立，也和風向卡、任務卡、加減分方式互相獨立。舊存檔缺欄位視為關。

## 2. 黑天鵝事件卡

### 2.1 牌堆

27 張：20 種事件各 1 張＋7 張「平靜」（約 1/4 的標的沒有事件）。開局洗牌（使用 state 內的 PRNG），每個標的抽 1 張，牌堆用完時重新建立並洗牌。

### 2.2 翻開時機

全員下注完成、決定股東順序之前自動翻開，**公開**顯示在標的卡上直到本標的結算。不新增階段。

### 2.3 用語

- **起始價 S**：本標的開始下注時的價格（100，或板塊連動計算出的值，見第 3 節）。
- **n**：本標的的消息總則數（通常＝玩家人數；「股東臨時會」時為人數＋1）。消息依序編號 1～n。
- **round**：四捨五入，.5 遠離 0。

### 2.4 效果

**A. 改變加減分**

| id | 名稱 | 效果 |
| --- | --- | --- |
| `circuit` | 熔斷 | 每一則的加減分限制在 −10～＋10 |
| `hype` | 題材炒作 | 第 1 則的加減分 ×2 |
| `whale` | 主力進場 | 第 n 則的加減分 ×2 |
| `exhausted` | 利多出盡 | 第 n 則的加減分正負反轉 |
| `fomo` | 散戶狂熱 | 每一則為正的加減分 ×1.5（round） |
| `panic` | 恐慌拋售 | 每一則為負的加減分 ×1.5（round） |
| `lull` | 量縮盤整 | 每一則的加減分 ×0.5（round） |
| `momentum` | 動能效應 | 第 2 則起，加減分再加上 round(前一則最終加減分 ÷ 2) |

**B. 改變價格**

| id | 名稱 | 效果 |
| --- | --- | --- |
| `exright` | 預告除權 | 第 ⌈n/2⌉ 則套用後，價格回到 100 |
| `shortcover` | 空頭回補 | 本標的第一次在某則套用後價格低於 60 時，立刻 +20（每標的一次） |
| `gap` | 跳空開盤 | 翻開時價格＝max(0, S＋隨機整數 −20～＋20)（PRNG）。起始價 S 不變，只有目前價格改變 |
| `limit` | 漲跌停板 | 每則套用後，價格限制在 max(0, S−50)～S＋50 |
| `rumor` | 謠言破滅 | 最後一則套用後、結算前，以 PRNG 隨機選 1 則消息，價格＝max(0, 價格 − 該則最終加減分) |

**C. 改變股東流程**

| id | 名稱 | 效果 |
| --- | --- | --- |
| `extra` | 股東臨時會 | 股東順序決定後，第一位股東再加到最後，本標的共 人數＋1 則消息 |
| `gag` | 封口令 | 第 1 則只能直接打出手牌（不能改寫、不能自訂）；手上沒有可直接打出的牌時才可改寫或自訂 |
| `reverse` | 逆序發言 | 股東順序改為「下注後剩餘籌碼」由少到多，同數依座位順序（取代隨機順序） |

**D. 改變結算（不影響價格）**

| id | 名稱 | 效果 |
| --- | --- | --- |
| `cancel` | 交易取消 | 最終價與 S 相差 5 以內（含）→ 全員退回押注，不分彩池、沒有名次 |
| `upset` | 爆冷門 | 依誤差**由大到小**排名後照原比例分配（並列處理與零頭規則不變） |
| `bailout` | 紓困加碼 | 銀行加碼 floor(彩池 × 50%) 一起分配；全場籌碼總數會增加 |

| id | 名稱 | 效果 |
| --- | --- | --- |
| `calm` | 平靜 | 無效果（7 張） |

### 2.5 每一則消息的計算順序

1. 原始加減分：主持人輸入（輸入時仍受風向卡正負限制），或投票平均 round 後套用風向歸 0。
2. 事件修正（只有本標的的那一張事件）：`hype`／`whale`／`exhausted`／`fomo`／`panic`／`lull`／`momentum`。
3. `circuit`：夾在 −10～＋10。
4. 價格＝max(0, 價格＋最終加減分)。
5. 價格事件：`exright`（第 ⌈n/2⌉ 則 → 100）、`shortcover`（首次 < 60 → +20）、`limit`（夾在範圍內）。
6. 若為第 n 則：`rumor` 扣回，接著結算（`cancel`／`upset`／`bailout` 在結算時套用）。

消息紀錄 `news[i]`：
- `delta`：最終加減分（任務「自己的消息造成的漲跌幅」讀這個值）。
- `rawDelta`：只有步驟 2～3 修正過時才有，記錄步驟 1 的值。
- `priceAfter`：步驟 5 之後的價格。
- `priceEvent`：步驟 5 有作用時記錄（`"exright"`／`"shortcover"`／`"limit"`），並記錄 `priceBeforeEvent`。

結算紀錄（`history[i]`）新增：`startPrice`、`event`、`gap`（跳空的隨機值）、`rumorIndex`、`rumorDelta`、`cancelled`、`bonus`（紓困加碼額）。

消息面在修正過的消息顯示「原始 → 最終」與事件名稱；價格事件顯示「事件名稱 → 價格」；謠言破滅在結算畫面標出被揭穿的那則。

### 2.6 與其他規則的關係

- 任務卡：`firstPlaceAtLeast` 在「交易取消」時不算第 1 名（沒有名次）；`allInOnce` 需拿回超過押注，退回押注不算。
- 「股東臨時會」時第一位股東發 2 則，兩則都會計入 `ownNewsSwing`。
- 紓困加碼讓全場籌碼增加；其餘事件籌碼守恆。

## 3. 板塊連動

- 開始下注（`startBetting`）時決定本標的起始價：
  - 本局歷史中有同類別的已結算標的 → 取**最近一個**的最終價 F，起始價＝max(0, 100＋round((F−100)×0.5))，round 為四捨五入、.5 遠離 0。
  - 沒有 → 100。
- `current.startPrice` 記錄起始價，`current.price` 從起始價開始；歷史紀錄也寫入 `startPrice`。
- 未啟用時起始價一律 100（行為與現在相同）。
- 自訂標的同樣依其類別連動。
- 下注畫面：顯示起始價；預測價格輸入框預設值改為起始價。標的卡在起始價不是 100 時註明「板塊連動：上一個同類別標的最終 F」。

## 4. 規則引擎修改（`toushou_core.js`）

- `config.blackSwanEnabled`、`config.sectorLinkEnabled`。
- `state.swanDeck`（開局建立）；`current.event`（id 或 `null`）、`current.startPrice`。
- 資料：`toushou_data.js` 新增 `SWAN_CARDS`（id、名稱 zh/ja、說明 zh/ja）與 `SWAN_COMPOSITION`。
- 新增純函式 `sectorStartPrice(state, category) -> number`、`modifyDelta(event, turnIndex, n, delta, prevDelta) -> number`。
- `placeBet` 全員下注完成時抽事件卡（`gap` 立即改價；`reverse`／`extra` 影響股東順序）；`newsError` 處理 `gag`；`commitDelta` 依 2.5 套用；`settleTarget` 增加選項 `{ reverse, bonus, cancel }`。
- `history[i]` 新增 2.5 所列欄位。

## 5. UI 修改（`toushou.js`）

- 開局設定兩個勾選框。
- 標的卡：顯示事件卡（名稱＋說明）與起始價註記。
- 消息面：原始→最終、除權標示。
- 下注：預測價預設值＝起始價。
- 結算與整局回顧：每個標的顯示起始價與事件。

## 6. i18n

`zh`、`ja` 新增 key；`en` fallback。

## 7. 驗證

1. `core_check`：牌堆組成 20＋7 與重洗；20 種事件逐一檢查（在正確的那一則生效、其他則不受影響、紀錄欄位）；計算順序（風向歸 0 之後才修正，熔斷在修正之後）；交易取消／爆冷門／紓困加碼的分配與守恆；封口令沒有可打出的牌時的例外；投票與主持人兩種模式都適用；板塊連動公式（160→130、40→70、45→72（−27.5 遠離 0 進位為 −28）、只看最近一個同類別、無同類別→100、未啟用→100）；舊存檔缺欄位。
2. `ui_check`：既有兩局維持通過；新增一局啟用黑天鵝＋板塊連動、2 個同類別標的，檢查起始價與事件顯示。
3. `multi_device_check`：維持通過（設定不變）。

## 1. 核心循環

### 1.1 一局的結構

- 單位是**週**，一局 24 週（暫定）。
- 每週流程：
  1. **事務所畫面（週初）**：看所屬 Vtuber 的狀態，排**行程板**（§4.2）。
  2. **企劃會議**：行程板上每一格「直播」各開 1 場會議（§2）。
  3. **直播**：玩家當管理員處理留言（§3）。
  4. **週報**：結算訂閱、收入、炎上度、好感、體力；抽週報事件（§4.10）。
- 第 24 週結束 → **結局判定**（§4.11）。

### 1.2 核心連動原則

會議中每張卡都會轉成直播參數（`streamConfig`，§5.3）：留言池權重、捲動速度、梗關鍵字、酸民比例、危險話題比例、超級留言機率、熱度上限。
因此**同一位 Vtuber、不同企劃 → 直播聊天室的手感完全不同**（例：恐怖遊戲＋深夜 → 大量尖叫梗與劇透酸民）。
直播表現（`streamResult`）再回頭影響週報數值。

### 1.3 失敗條件

- 任一 Vtuber 炎上度達 100 → 炎上事件：休播 2 週、訂閱與好感大降（§4.1）。
- 事務所資金歸零 → 遊戲提前結束（壞結局）。

### 1.4 存檔

localStorage，每週週報結束自動存檔；P1 單一存檔槽。鍵：`pritest-vkikaku-save`。只有 `vkikaku_save.js` 讀寫。

## 2. 企劃會議

### 2.1 企劃卡的四個欄位

每場直播四個欄位各放 1 張卡：

| 欄位 | 例子 | 影響直播的什麼 |
|---|---|---|
| 類型 | 遊戲實況、歌回、雜談、凸待、ASMR、料理 | 基本留言池、捲動速度 |
| 題材 | 恐怖遊戲、高難度遊戲、懷舊歌、話題新作、棉花糖 | 梗關鍵字、劇透／指示廚等危險留言的比例 |
| 噱頭 | 耐久、懲罰遊戲、新衣裝公開、初見、限定周邊預告 | 超級留言機率、熱度上限、風險 |
| 時段 | 早上、晚上黃金時段、深夜 | 同接人數、酸民比例 |

每張卡帶 1～2 個**標籤**（恐怖、可愛、音樂、競技、深夜、懷舊…），用於組合（§2.4）與個性反應（§2.5）。
事務所持有一副企劃卡組（P1 初始約 24 張），每場會議抽 6 張為手牌。

### 2.2 回合制談判（P1）

- 每場會議有 **5 個發言回合**。每回合做一件事：**出卡**（放進欄位或替換）、**換牌**（棄 1 抽 1）、**說服**（§2.6）、**調查**（§2.5）。P2 加上「用道具」。
- 回合用完欄位還沒湊齊 → 該欄位用「普通」預設卡補上，並扣 Vtuber 心情。

### 2.3 雙滿意度條（P1）

- 會議桌上有 **Vtuber** 與**營運部長**，各有一條滿意度（0～100）。
- Vtuber 在意：個性偏好、體力、心情。營運部長在意：預估收入、炎上風險、趨勢符合度。
- 兩條都要達到門檻（暫定 50）才能直接開播。未達門檻也能強行開播，但未達者的不滿會反映在直播（Vtuber：心情－；部長：週報資金獎勵－）。

### 2.4 卡牌組合（Combo）（P1）

四欄位的標籤湊齊特定條件形成具名組合，像撲克牌型。例：

- **深夜恐怖**（恐怖題材＋深夜）：同接＋、尖叫梗浪潮增加；Vtuber 怕恐怖時心情－但精華片段機率＋
- **歌回耐久**（歌回＋耐久）：超級留言＋＋、體力消耗大
- **全標籤一致**（4 張同標籤）：大組合，熱度上限提高

P1 放約 12 種組合，定義在 `vkikaku_data.js`；觸發過的組合記錄在圖鑑（存檔內）。

### 2.5 隱藏偏好與調查（P1）

- 每位 Vtuber 有 2～3 個**公開個性標籤**與 2～3 個**隱藏標籤**（隱藏地雷／隱藏最愛）。
- 「調查」（花 1 回合）：揭露 1 個隱藏標籤，永久記錄。
- 誤踩隱藏地雷 → 心情大扣並揭露；打出隱藏最愛 → 「這個我超想做！」加成並揭露。
- 卡片放上去時即時顯示 Vtuber 表情與一句台詞：喜歡／普通／不喜歡（不喜歡 → 產生顧慮，§2.6）。

### 2.6 說服小遊戲（P1）

- Vtuber 不喜歡某張卡時提出 1～2 個**顧慮**：「怕被罵」「最近很累」「不擅長」等。
- 玩家花 1 回合，從**說服牌**中出牌對應顧慮。P1 有 4 種：**數據**（對「怕沒人看」）、**鼓勵**（對「不擅長」）、**讓步**（對「很累」，但效果打折）、**承諾**（萬用）。
- 對應正確 → 顧慮消除、好感小＋。錯誤 → 心情－。
- 「承諾」可以強行消除任何顧慮，P2 起會留下**約定**（§2.9）。
- 說服牌由事務所等級與好感解鎖。

### 2.7 趨勢（P1）

每週 1～2 個「本週流行」標籤，符合的卡同接加成、部長滿意度＋。給玩家打出 Vtuber 不擅長的卡的理由。

### 2.8 確認畫面（P1）

四張卡定好後顯示預測：同接範圍、炎上風險星等、預估超級留言、觸發的組合；按「開播」進入直播。

### 2.9 P2 追加

- **預算與道具**：每場有預算，可買新衣裝、合作遊戲版權、宣傳廣告、麥克風等道具（＝特殊卡，可補欄位或加標籤）。花太多 → 部長滿意度－。
- **同接預測押注**：開播前押區間（保守／普通／挑戰），結果落在區間內給資金或部長滿意度，挑戰區間獎勵大。
- **會議突發事件**：撞題材、合作邀約、Vtuber 喉嚨不舒服等，打亂原本的組合。
- **約定**：用「承諾」說服後留下約定（例：「下週讓我休息」），沒遵守則好感大扣。

## 3. 直播（管理員挑留言）

### 3.1 畫面（P1）

- 左：Vtuber 立繪（表情隨氣氛）、直播標題、同接數、**熱度條**。
- 右：**聊天室**，留言由下往上捲動。
- 下：管理工具列（技能與冷卻）。
- 一場 75 秒（暫定），分 3 段：開場 → 中盤 → 收尾（高潮），各段留言組成不同。

### 3.2 留言種類與操作（P1）

點一則留言後選操作：**念**（再選語氣，§3.4）或**刪**；酸民可**封鎖**（同帳號之後的留言全消）。

| 留言 | 正確操作 | 漏掉或處理錯的後果 |
|---|---|---|
| 好梗／有趣提問 | 念 → 熱度＋ | 漏掉不罰，只是少加分 |
| 超級留言 | 念（一定要念），金額越高越重要 | 漏掉 → 收入減、金主不滿 |
| 普通留言 | 不用管 | 念了只加一點熱度 |
| 劇透／指示廚 | 刪 | 念到 → 熱度－ |
| 酸民 | 刪，連續出現就封鎖 | 放著 → 擴散成更多酸民 |
| 危險話題（其他事務所、個資、敏感時事） | 刪，必須在捲出畫面前處理 | 捲出畫面 → 炎上度大增 |
| 偽裝留言（看似好梗但藏地雷字） | 刪 | 念了 → 炎上度＋ |

### 3.3 基本機制（P1）

- **連擊**：連續正確處理累積連擊，熱度加成；處理錯中斷。
- **梗浪潮**：企劃的梗關鍵字讓同梗留言一波波湧上；在浪潮中念到「起源」留言 → 熱度大爆。
- **Vtuber 狀態**：心情低時念的效果打折。
- **管理工具（有冷卻）**：慢速模式（捲動變慢 5 秒）、會員限定（酸民與危險話題暫減，但同接成長停止）、釘選（釘一則好留言持續加熱度）。
- **精華片段**：熱度達頂峰時進入「精華時刻」，此時念到好留言會被剪成精華，週報時加訂閱。

### 3.4 回應語氣（P1）

「念」之後從 4 方向輪盤選語氣：**吐槽／撒嬌／認真／帶過**。

- 每則留言有適合語氣（梗→吐槽、應援→撒嬌、提問→認真、微妙→帶過）。對上 → 熱度大加、連擊；不對 → 效果減半。
- Vtuber 個性偏好某些語氣（例：話多的吐槽加成），所以同一則留言不同 Vtuber 的最佳答案不同。

### 3.5 觀眾陣營（P1）

同接由四個陣營組成：**核心粉／路人／海外觀眾／酸民**，前三者各有滿意度。

- 念核心粉的內梗 → 核心粉＋、路人可能－；念海外留言 → 海外＋。
- 結束時：路人滿意度 → 新訂閱；核心粉滿意度 → 超級留言與會員；酸民比例過高 → 炎上風險。

### 3.6 常客（P1：每位 Vtuber 5 位）

- 固定 ID、頭像、說話習慣（例：每次第一個打招呼、愛講冷笑話、只會打「草」）。
- 念到常客 → 該常客好感＋；好感高的常客會在危機時幫忙（帶頭刷應援、替你壓下酸民）。
- P2：長期忽略或誤刪 → 常客**黑化成酸民**，之後的直播會回來；常客記錄在事務所「粉絲名冊」。

### 3.7 話題分支（P1）

念某些「話題留言」讓 Vtuber 開啟一段話題，之後 10 秒的留言組成改變。好分支引出梗浪潮，壞分支（敏感話題）讓危險留言暴增；念之前要判斷這則會把話題帶去哪。話題留言在畫面上有小圖示提示方向（可能誤導，例：看似日常其實通往敏感話題）。

### 3.8 直播任務（P1：公開任務；P2：隱藏任務）

- 每場開播前顯示 1 個**公開任務**（來自企劃，例：歌回「念到 3 則點歌留言」）。
- P2：另有 1 個**隱藏任務**，直播中達成才揭露。
- 達成 → 額外訂閱或解鎖新企劃卡。

### 3.9 招牌技（P1）

熱度條滿 → 可發動該 Vtuber 的招牌技（每位 1 招，一場最多 2 次）。例：歌姬型「高音爆發」把畫面上所有留言變讚嘆、清除酸民；恐怖苦手型「大尖叫」立刻觸發梗浪潮。

### 3.10 危機事件（P1：炎上火種；P2：洗版、突襲）

每場最多 1 次：

- **炎上火種**（P1）：一則危險留言開始被引用擴散，形成引用樹；要在擴散前刪掉源頭與引用。
- **洗版攻擊**（P2）：大量相同留言湧入，混著真正的超級留言。
- **突襲**（P2）：其他 Vtuber 帶觀眾來，留言速度 ×2，接住 → 大量新訂閱。

### 3.11 P2 追加

- **聊天室投票**：中段出現投票事件，玩家依最近留言風向猜多數派，選擇照多數（滿意）或選冷門（風險大、精華機率高）。
- **管理技能樹**：玩家（管理員）有經驗值，升級時三選一解鎖技能（酸民高亮、SC 音效提示、輪盤快捷鍵、慢速模式冷卻－等）。

### 3.12 結算與評價（P1）

結束後顯示：最高同接、平均熱度、處理正確率、陣營滿意度、超級留言收入、漏掉的危險話題數、精華片段數、任務；給 **S/A/B/C/D** 評價。結果打包成 `streamResult` 交給事務所核心。

### 3.13 留言內容（P1）

- 模板＋詞庫組成（例：「{遊戲}的{角色}好可愛」），zh／ja 兩種語言；英文 fallback 到 ja。
- P1 每種留言 30～50 個模板，放 `static_src/vkikaku_chat_data.js`。
- 留言的種類、適合語氣、陣營、話題分支、是否偽裝，都是資料欄位，不從文字推斷。

### 3.14 時間與輸入

- 直播以固定時間步推進（1 步＝50ms，75 秒＝1500 步）。
- 玩家輸入記錄為 `{step, commentId, action, tone}`；核心只吃 `streamConfig`＋種子＋輸入紀錄，同樣輸入必得同樣結果（可重播、可 Node 驗證）。

## 4. 事務所經營

### 4.1 Vtuber 的數值（P1）

| 數值 | 範圍 | 說明 |
|---|---|---|
| 訂閱數 | 0～ | 主要成績 |
| 體力 | 0～100 | 直播消耗，休息回復；<30 直播表現打折，0 → 強制休播 |
| 心情 | 0～100 | 會議與直播影響；影響念留言效果 |
| 好感（對玩家） | 0～100 | 說服成功率、說服牌解鎖、結局分支 |
| 炎上度 | 0～100 | 100 → 炎上事件（休播 2 週、訂閱與好感大降）；每週自然下降 |
| 技能 | 歌唱／遊戲／雜談／企劃力 1～10 | 對應類型卡加成，直播後依類型成長 |
| 個性標籤 | 公開 2～3＋隱藏 2～3 | 會議反應、偏好語氣、招牌技 |

### 4.2 行程板（P1）

- 每位 Vtuber 每週一張 **7 格行程板**（週一～週日），放行程卡：**直播、練習、休息、宣傳、SNS、收錄**；P1 大型企劃準備期另有「準備」格（§4.5）。
- **相鄰加成**：練習→直播（該類型＋）、宣傳→直播（同接＋）、收錄→休息（不扣心情）。
- **疲勞連鎖**：連續 3 格高強度 → 體力大扣，觸發「過勞」事件。
- **設備共用**：錄音室一天只能一人用（收錄格互斥），排程成為輕度拼圖。
- P1 每週直播上限：全事務所 2 場（暫定）。

### 4.3 SNS 發文（P1）

行程放 SNS 時選一則發文（預告、日常、梗圖、跟風話題）。

- 好發文 → 下一場直播同接＋，或**提前埋梗**（下次直播出現該梗浪潮）。
- 跟風熱門話題 → 爆紅或炎上二選一，機率依個性與當前炎上度。

### 4.4 事務所資源（P1）

- **資金**：超級留言與會員收入進帳；每週固定支出（薪水、器材）。歸零 → 遊戲結束。
- **事務所等級**：依總訂閱數升級，解鎖企劃卡、說服牌、管理工具、Vtuber 名額。
- **卡組管理**：週報時從獎勵中三選一加入新企劃卡，或刪除一張卡。

### 4.5 大型企劃（P1：生日 3D 直播；P3：其他）

- 每位 Vtuber 有路線（歌手／遊戲大會／綜藝），達成條件可開啟大型企劃：**生日 3D 直播**（P1）、單曲發行、遊戲大會出場、周年紀念（P3）。
- 準備 2～4 週：行程板放「準備」格累積準備度、湊資金。
- 當週是**特別直播**：留言量 ×2、危機事件必定出現，評價決定是否達成里程碑。是結局分支的主要依據。

### 4.6 Vtuber 關係（P1：2 人間）

- 同事間有關係值（好友／普通／對手意識）。
- 排程偏心某人 → 其他人嫉妒、心情－。
- 週報關係事件（「A 想跟 B 聯動」「C 覺得被冷落」）。聯動直播本身在 P3。

### 4.7 年曆活動（P1：2 個；之後補齊）

24 週中有固定季節活動（P1：夏祭、周年；之後加萬聖節、聖誕），該週有特別企劃卡與趨勢加成；錯過沒有懲罰。

### 4.8 Vtuber 陣容（P1）

- **2 位**原創 Vtuber：怕恐怖的歌姬型、夜貓子遊戲型（名字與設定在 P1 計畫中定）。
- 立繪表情 4 種（普通／開心／害怕／生氣），先用 CSS 與 SVG 簡易繪製。

### 4.9 P3 追加

- **招募**：甄選小遊戲，看試播片段判斷潛力，隱藏個性只揭露一部分。
- **聯動直播**：兩位一起開，個性組合產生新組合與新梗。
- **對手事務所與排行榜**：2 家 AI 對手，每週公布同接／訂閱排行；同週打同一流行標籤 → 同接被分走。
- **工作人員**：剪輯師、繪師、音響、經紀助理，付薪水換被動效果，名額有限。
- **周邊商品**：選種類與數量，賣光大賺、庫存過多虧損；銷量受核心粉滿意度與最近評價影響。

### 4.10 週報事件（P1：約 10 種）

每週週報後抽 0～1 個事件，部分有選擇（影響好感或資金）。例：「剪片師把精華剪爆了」「其他事務所挖角」「Vtuber 想挑戰新類型」。

### 4.11 結局（P1：4 種）

第 24 週依總訂閱、資金、每位 Vtuber 的好感與里程碑（10 萬訂閱、生日 3D 成功等）判定。資金歸零為獨立的壞結局。

### 4.12 數值管理

所有數值暫定，集中在 `static_src/vkikaku_data.js`。

## 5. 架構、檔案、驗證

### 5.1 原則

- 規則核心不碰 DOM、不讀寫 localStorage，只用允許的運算與確定性亂數（種子＋`Math.imul` 的 mulberry32 類演算法）。
- 直播用固定時間步；UI 只把輸入送進核心，核心不讀真實時間。
- 每個遊戲獨立 JS／CSS／字串（CLAUDE.md §5.2.1）。

### 5.2 檔案

| 檔案 | 內容 |
|---|---|
| `static_src/vkikaku_data.js` | 數值、Vtuber、企劃卡、組合、說服牌、行程卡、SNS 發文、事件、結局條件 |
| `static_src/vkikaku_chat_data.js` | 留言模板、詞庫、常客（zh／ja） |
| `static_src/vkikaku_rng.js` | 確定性亂數 |
| `static_src/vkikaku_meeting.js` | 會議規則 → 輸出 `streamConfig` |
| `static_src/vkikaku_stream.js` | 直播規則：留言生成、捲動、判定、陣營、浪潮、話題分支、危機、招牌技、評價 → 輸出 `streamResult` |
| `static_src/vkikaku_office.js` | 週循環、行程板、SNS、大型企劃、關係、週報事件、結局 |
| `static_src/vkikaku_save.js` | 存檔格式、版本遷移、localStorage（唯一碰 storage 的檔） |
| `static_src/vkikaku_ui_*.js` | 畫面（事務所、會議、直播、週報、結局），只碰 DOM，不含規則 |

| `site_src/vkikaku_page.py` | 頁面（`page_shell(..., paid=True, extra_styles=("css/vkikaku.css",), extra_i18n=("i18n/vkikaku.js",))`） |
| `site_src/i18n_vkikaku.py` | 字串，前綴 `vk_` |
| `generate.py`、`site_src/projects.py`、`site_src/i18n_data.py`、`tools/split_css.py` | 註冊頁面、pay 分頁、`GAME_I18N_PREFIXES`、CSS 前綴 |

### 5.3 資料流

```
office（行程板） ──► meeting（卡、回合、說服） ──► streamConfig
streamConfig ＋ seed ＋ inputLog ──► stream ──► streamResult
streamResult ──► office（週報、事件、結局） ──► save
```

三個核心之間只傳 `streamConfig`、`streamResult` 兩個純資料物件；欄位在 P1 實作計畫中定義。

### 5.4 驗證

- `node --check static_src/vkikaku_*.js`
- `tools/vkikaku_check/core_check.js`（Node）：
  - 確定性：同 `streamConfig`＋種子＋輸入 → 同 `streamResult`。
  - 每個組合都能被觸發；留言種類比例符合 `streamConfig`（統計範圍檢查）。
  - 自動 AI 玩完 24 週不出錯，所有數值在範圍內。
  - 存檔往返一致。
- Playwright 臨時腳本（不提交）：開頁前 `localStorage.setItem("pritest-pay-unlocked", "1")`；走完一週（排程 → 會議 → 直播 → 週報）；按鈕一律 `dispatchEvent`。

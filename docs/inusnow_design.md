### 2.3 資料格式（每個雪場一個 JSON）

```
static_src/inusnow/data/<id>.json
{
  v: 1, id, name: {ja, zh, en}, pref: {ja, zh, en}, attribution: [2 筆],
  origin: {lat, lon},             // 西北角；x＝往東、z＝往南（公尺），兩者都 ≥ 0
  grid: {w, h, cell: 10, base, scale: 0.1, enc: "pred2d-int16le-deflate-base64", data: "..."},
  pistes: [{id, osm: [wayId...], name: {ja, zh?, en?}, diff, width, len, drop, pts: [[x, z], ...]}],
  areas: [{osm, diff, pts}],      // 面狀雪道（目前只當資料保留）
  lifts: [{name, pts}],           // 纜車（景觀；P2 自由滑行用來上山）
  events: {gs: {piste}},          // P2 加上 slope、cross
  notes: ""
}
static_src/inusnow/data/index.json   // 雪場清單用：{v, resorts: [{id, name, pref, gs: {piste, name, diff, len, drop, width}, kb}]}
```

- 高度：`q＝round((h−base)÷scale)`；存 `q − (左＋上−左上)` 的二維預測誤差（第一列只用左、第一行只用上），Int16LE、deflate（zlib 格式）、base64。
  瀏覽器用 `DecompressionStream("deflate")`，Node 用 `zlib.inflateSync`。
- 格網只涵蓋所有雪道外擴 150 m 的範圍；雪道 150 m 內原精度，外面為 40 m 粗格網的雙線性內插（背景用）。
- 遊戲載入地形時做 `PHYS.blurPasses`（2）次 3×3 平均模糊（壓雪後的平順坡面）。
- 雪道寬度依難度預設（novice 45、easy 40、intermediate 35、advanced 30、expert／freeride 25 m）。
- 座標轉換（只在建置工具）：`x＝(lon−lon0)×111320×cos(lat0)`、`z＝(lat0−lat)×110540`。

### 2.4 雪道指南的使用規則

- 只確認事實，不複製表現：不描圖、不截圖、不把圖片放進 repo。
- 用途：補 OSM 缺的雪道名稱、確認難度、確認公園與比賽用雪道。
- 修正寫進該雪場 JSON 的 `notes`（由 `resorts.py` 的 `notes` 帶入），例如「依 2026 年雪道指南確認：第 3 ゲレンデ的公園位置」。

## 3. 物理（單板；實作 `inusnow_phys.js`）

固定步長 1/60 秒。係數在 `inusnow_data.js` 的 `PHYS`（括號內為目前值）。

### 3.1 狀態

`{p: [x, y, z], v: [vx, vy, vz], h: [hx, hz], air, crouch: 0..1, edge: −1..1（畫面用）, yawAir（空中累計轉角，rad）, airSteps, fall（摔倒剩餘步數）, t, mods, boost}`

- `h` 是板頭方向的水平單位向量。往右轉（輸入 `s > 0`）：`h ← normalize(h + ω·dt·(−hz, hx))`。
- 地面高度：格網雙線性內插；法線：雙線性面的解析梯度 `(−∂h/∂x, 1, −∂h/∂z)` 正規化。

### 3.2 每一步（地面）

1. 摔倒中（`fall > 0`）：速度每步 ×0.94，不接受轉向。
2. 速度投影到坡面；加上重力切向分量 `g − (g·n)n`（g＝9.8）。
3. 轉向：`ω＝(s/8)·turnBase(2.4)·技巧 ÷ (1＋速度/turnSpeedRef(15)) ×(1 − crouchTurn(0.4)·crouch)`。
4. 板子在坡面上的方向 `b`；速度在板子後方時視為反腳滑行（`b` 反向，不算失誤）。
5. 速度拆成沿板分量與側向分量 `lat`。可消掉的側向速度 `cap＝gripAccel(16)·雪質抓地·平衡·dt`：
   - `lat ≤ cap`：**刻滑**，速度轉到板子方向，大小 ×(1 − carveLoss(0.002)·lat)。
   - `lat > cap`：**橫滑**，只消掉 `cap`，再減速 `skidDecel(7)·力量修正·dt·(1 − cap/lat)`；超出 1.2 m/s 時記 `skid` 事件。
6. 雪面摩擦：速度減 `μ·g·n_y·dt`。
7. 起跳（`j＝1`）：速度加 `n·vOllie(2.6)·勇氣`，進入空中，記 `ollie`。

### 3.3 空中與落地

- 空中：只有重力與空氣阻力；轉向輸入改成轉體：`ω＝(s/8)·spinRate(2.6)·技巧`，`yawAir` 累計。
- 每一步最後：空氣阻力 `v ×(1 − kAir(0.0085)·體型修正·(1 − crouchDrag(0.45)·crouch)·|v|·dt)`，移動。
- **離地**：移動後若高於地面超過 `takeoffGap`（0.12 m）就進入空中（記 `takeoff`）。
- **落地**（低於地面時）：`c＝|h·水平速度方向|`
  - `c ≥ landClean(0.866)·(2 − 平衡修正)` 或空中不到 6 步 → **乾淨**（`land`）
  - `c ≥ landSketchy(0.5)` → **不穩**（`sketchy`），速度 ×0.6
  - 否則 → **摔倒**（`fall`），速度 ×0.2，停 90 步（1.5 秒），板頭對齊速度方向
- 反腳落地允許，所以轉體 180° 的倍數自然乾淨落地；轉了 90° 左右就會摔倒。

### 3.4 犬種能力 → 乘數

`statMul(v)＝0.85＋0.3·v/100`（能力 1～100 → 0.85～1.15）。

| 能力 | 影響（`dogMods`） |
|---|---|
| 平衡 bal | 抓地 `grip`、落地 `land` |
| 力量 pow | 橫滑減速 `skid＝2−statMul`；`push`（P2 興奮度的加速） |
| 勇氣 brv | 起跳 `ollie` |
| 技巧 tec | 轉向 `turn`、轉體 `spin` |
| 體型 siz | 空氣阻力 `drag＝2−statMul`（大狗每單位質量阻力小） |
| 耐寒 cld | P3 天氣（§18.3） |

### 3.5 地形附加物（P2 起；跳台、鐵管、波浪、護牆）

為了保持確定性，跳台等地形**不改格網**，而是在高度上疊加解析的形狀函式（只用加減乘除）：

```
heightAt(x, z) = 格網高度 + Σ feature.offset(x, z)       // 只加總包圍盒內的附加物
normalAt(x, z) = 有附加物時用中央差分（±0.25 m）求梯度，否則用格網的解析梯度
```

附加物在自己的座標系（中心點、沿雪道單位向量 `t`、右側 `r`）中定義，`u`＝沿 `t` 的距離、`w`＝沿 `r` 的距離：

| 種類 | 形狀（offset） | 參數（暫定） |
|---|---|---|
| `kicker` 跳台 | `u∈[−L, 0]`：`H·((u+L)/L)²`；`|w| > W/2` 時在 1 m 內線性收到 0；`u > 0` 為 0（唇口之後直接掉回原坡面） | S：L 6、H 1.2、W 6；M：L 9、H 2.0、W 7；L：L 12、H 3.0、W 8 |
| `roller` 波浪 | `x＝u/(len/2)`，`|x| ≤ 1`：`A·(1−x²)²` | A 0.8～1.4、len 8～12 |
| `bank` 護牆 | 外側 `side·w > d0`：`B·min(1, (side·w−d0)/dw)²`，沿 `u` 兩端 4 m 收到 0 | B 2.5、d0＝雪道半寬−6、dw 5 |
| `rail`／`box` | 不改地形；是一條離地 0.6 m 的線段（見 §17.2 滑桿） | rail 長 8、寬 0.3；box 長 6、寬 0.6；前方附 2 m 長、0.6 m 高的上桿台（kicker 形狀） |

- 附加物清單由 seed 與雪道決定（§17），存在比賽物件 `run.feats`，傳給 `Terrain` 的包裝 `T.withFeatures(terrain, feats)`；物理一律透過這個包裝取高度與法線。
- 畫面用同一份清單產生網格（kicker、roller、bank 依 offset 函式取樣成 mesh，rail／box 用圓柱與方塊）。

### 3.6 輸入與紀錄

- 每步輸入：`{s: −8..8 轉向, c: 0/1 蹲低, j: 0/1 起跳, g: 0..6 抓板}`；P2 加上 `z: 0/1`（興奮度發動，§17.5）。
- 編碼：`code＝(s+8) + 17·(c + 2·(j + 2·g))`（< 476）；有 `z` 時再 +476（舊紀錄不受影響）。行程長度編碼成 `code36[.count36]` 以逗號連接。
- 同一份「雪場資料＋賽事參數＋seed＋紀錄」→ 每一步結果完全相同（Node 與瀏覽器實測一致）。

- 比賽物件 `run`：`{terrain, opts: {piste, seed, dog, snow, runNo}, piste, gates, finish, st, next, perfect, chain, still, near, status: "run"|"finish"|"dsq", reason: "miss"|"off"|"stop"|"time", missGate, steps, inputs, events: [{k, e, n?}], time}`。
- 事件：`ollie`、`takeoff`、`land`、`sketchy`、`fall`、`recover`、`skid`、`gate`、`perfect`。

## 16. 共通規則（P2 以後都適用）

- 新的賽事都寫成 `inusnow_<賽事>.js`（例：`inusnow_slope.js`、`inusnow_cross.js`），掛在 `PriTestInusnowCore` 或自己的命名空間；遵守 §11 的確定性限制，並加進 `core_check.js` 的原始碼掃描清單。
- 一場比賽的所有亂數都由 `raceSeed` 衍生（`makeRng(raceSeed ^ hash("<用途>"))`），不用 `Math.random`；畫面上的台詞、特效挑選才可以用 `Math.random`。

- 新增的「暫定」數值都放 `inusnow_data.js`。
- 每個新畫面都要在 `ui_check.js` 加上能用 `dispatchEvent` 走完的流程。

### 17.2 Slopestyle

**賽道**（`inusnow_slope.js`：`makePark(terrain, pisteId, seed) → feats`）：
- 依序 6 個地形，間隔 70～90 m：`box`、`rail`、`kicker S`、`kicker M`、`kicker L`、`rail`（暫定；seed 只決定細節：側向偏移 ±4 m、跳台大小在同級內 ±10%）。
- 第 1 個地形離起點 60 m；終點線在最後一個地形後 60 m。
- 出發初速 6 m/s；上限 150 秒（U2）；離雪道邊緣 60 m 以上＝失格（0 分）。

**滑桿（rail／box）**：
- 選手在上桿台頂端（離地 0.6 m）時，位置在滑桿寬度 ±0.4 m 內 → 進入 `grind` 狀態；位置沿滑桿方向移動、高度固定在滑桿頂、μ＝0.02、轉向輸入改成維持平衡。
- 板子與滑桿方向的 `|cos|`：≥ 0.866＝**50-50**；≤ 0.5＝**板滑（boardslide）**；之間＝失去平衡（不穩：掉下滑桿、速度 ×0.7）。
- 進桿前在空中轉了 ≥ 160°＝**轉上（spin-on）**；離桿時轉 ≥ 160°＝**轉下（spin-off）**。
- 滑完的比例 `cover`＝滑過的長度 ÷ 滑桿長度。

**空中技巧**（每次 `takeoff`/`ollie` 到落地為一次）：
- 轉體角度＝`|yawAir|` 換算度數，四捨五入到 180 的倍數（0、180、…、1440）。
- 抓板：空中按住 `g`（1～4：Indy、Melon、Nose、Tail；5＝**咬尾抓板**）；同一個 `g` 持續 ≥ 18 步（0.3 秒）才成立，取持續最久的那個。
- **咬尾抓板（S1）**：只有轉體 ≥ 360° 時成立，否則視為沒有抓板。
- **空中吠叫（S1）**：空中按 `g＝6` 一次（每次空中只算一次）。
- **落地甩雪（S1）**：乾淨落地後 18 步內按任一抓板鍵 → 成立。
- 高度＝空中最高點與起跳點的高度差。

**計分**（每個地形一個分數；沒有在地形上做技巧＝0 分）：

| 項目 | 分數（暫定） |
|---|---|
| 難度 D（空中） | 轉體 0°:10、180:20、360:35、540:50、720:65、900:78、1080:88、1260:95、1440:100 |
| 難度 D（滑桿） | 50-50 25、板滑 35；轉上 +15、轉下 +15；×(0.4＋0.6·cover) |
| 抓板 | +8；咬尾抓板 +12 |
| 高度 A | `min(20, 高度m × 4)`（只有空中） |
| 吠叫／甩雪 | 各 +5 |
| 完成度 E | 乾淨 1.0、不穩 0.6、摔倒 0 |
| 重複 | 同一個（轉體、抓板、滑桿技巧）組合第 2 次以後 ×0.6 |

- 地形分數＝`(D＋抓板＋A＋吠叫＋甩雪) × E × 重複`。
- 一趟分數＝`min(100, 6 個地形分數合計 ÷ 6 × 1.1)`。
- 3 位評審：一趟分數＋各自偏差（`makeRng(raceSeed ^ hash("judge"))` 產生，−3.0～+3.0，每趟每位評審不同），取平均到小數點一位。
- 2 趟取高分。

**CPU（Slopestyle）**：沿 `autopilot` 的路線改成「地形中心點的連線」；到 kicker 前 0.5 秒蹲低；空中依等級選目標轉體（等級 1:360、2:540、3:720、4:900、5:1080，±180 由 rng 決定），轉到目標 −20° 就停止轉向；抓板依風格固定一種；滑桿選 50-50 或板滑。

**畫面**：地形附加物的網格、滑桿；空中顯示技巧名稱與分數；成績顯示每個地形的分數明細、3 位評審分數。狗的姿勢：抓板時一隻前腳伸向板子、咬尾時頭轉向尾巴、甩雪時身體左右晃。

### 17.4 Snowboard Cross

**賽道**（`inusnow_cross.js`：`makeCross(terrain, pisteId, seed) → feats`）：

**比賽**：

### 18.1 競猜（B1、B2、B5）

### 18.2 教練模式（D3）

### 18.6 M1 救難犬任務

## 19. 第 4 階段規格（即時同場）

### 19.1 房間協定

- 比照 saigo（`saigo_net.js`）：用 `game_storage.js` 的 `rtSet`／`rtSubscribe`／`rtTransaction`／`rtSetWithOnDisconnect`，路徑 `games/<roomId>/rtState/inu/...`（不用改 `database.rules.json`）。**實作前先讀 `saigo_net.js` 與 `game_storage.js`。**

```
inu/meta            { v: 1, host: cid, no: 場次, status: "lobby"|"card"|"race" }
inu/on/<cid>        true（onDisconnect 移除）
inu/pl/<cid>        { name, breed, lane, ready, no, role: "ride"|"watch" }
inu/cfg             JSON：房主設定（雪場、賽事、雪質、天氣、趟數）
inu/m/<no>          { card: JSON（含 raceSeed、各選手的賽道與犬種）, startAt: 伺服器時刻 ms }
inu/m/<no>/rec/<cid>/<k>   第 k 段輸入紀錄（每 0.5 秒＝30 步一段，編碼同 §3.6）
inu/m/<no>/done/<cid>      { status, time|score }（自己算的結果；大家會再重算確認）
inu/m/<no>/bets/<pid>      觀戰者的下注（§18.1 的票）
inu/m/<no>/cmd/<pid>       教練模式指令（§18.2）
inu/bal/<pid>       { c: 房間狗幣, ver, name }（transaction）
```

- 依伺服器時刻 `startAt` 同時出發；每台裝置模擬自己的狗，每 30 步把新的一段紀錄寫上去。
- 其他人的狗：拿到的紀錄重播到最新一步，之後用最後的速度外插（最多 1.5 秒）；落後超過 3 秒沒有新紀錄＝斷線，結算時算到最後一步（未完賽）。
- 結算：所有人用完整紀錄重算，結果一致後才派彩；`done` 和重算不同時以重算為準。

### 19.2 4 人平行大曲道（Q4）

- 只在雪道平均寬度 ≥ 30 m 的雪道開放。4 條賽道中心線＝雪道中心線往兩側偏移 `(k−1.5)·laneW`，`laneW＝min(9, 雪道寬/4)`。
- 每條賽道的旗門：同一組 seed 的側向偏移 × `laneW/雪道寬` 縮小後套用；同一座旗門在 4 條賽道的 `s` 相同（並排）。
- 選手之間不碰撞（各自在自己的賽道上判定旗門；誤闖別人的賽道＝漏門）。
- 第 2 趟換賽道（1↔4、2↔3），兩趟合計。

### 19.3 M6 雪橇犬接力

- 一隊 4 隻（多人時每人一棒；單人時其他棒由 CPU），4 棒：大曲道（該雪場大曲道的前半）→ Cross（Cross 雪道，單獨滑、無對手）→ Slopestyle（`(100 − 分數) × 0.1 秒` 加進時間）→ 大曲道後半。
- 下一棒在上一棒完成時出發；團隊時間＝4 棒合計。對手是 CPU 隊伍的模擬成績。

### 19.4 R5 精彩重播

- 從紀錄自動找出：最快的 10 秒區段（平均速度最高）、最大的一跳（高度）、分數最高的技巧、Cross 的超車。
- 成績畫面「精彩重播」：依序以轉播鏡頭播放；分享碼＝§13 的分享碼＋`|h:<起步>-<終步>` 片段。

## 20. 第 5 階段規格（成長與收集）

### 20.1 技術等級

- 經驗：完賽 +20、比賽模式名次（1～3 名 +30／+20／+10）、Slopestyle 每個 ≥ 360° 的技巧 +2、自由滑行每個雪道章 +10。
- 升級需要 `100 × 目前等級`；每升 1 級得到 3 點能力點，分配到 6 項能力，每項上限＝犬種基礎值 +25（最高 100）。
- 能力加點存在 `statsAdd: {breed: {bal, ...}}`（每個犬種分開）。

### 20.2 裝備（狗幣購買）

| 種類 | 選項（暫定） | 效果 |
|---|---|---|
| 雪板 | 長度 短／中／長 × 硬度 軟／硬（6 種） | 短：轉向 +6%、空氣阻力 +3%；長：反之；軟：轉體 +8%、抓地 −4%；硬：反之 |
| 固定器 | 3 種 | 抓地 +0／+3／+6% |
| 雪鏡 | 3 種 | 霧的距離 ×1／×1.3／×1.6 |
| 雪衣 | 3 種 | 耐寒 +0／+10／+20 |
| 雙板（§20.10） | 3 種長度 | 見 §20.10 |

### 20.3 打蠟與解鎖

- 打蠟 4 種（各對應一種雪質），每場比賽消耗 1 個：選對 μ ×0.9、選錯 μ ×1.05；沒打蠟 ×1.0。
- 雪場解鎖：一開始開放八方、苗場、手稻；每個新雪場的條件＝「已開放的任一雪場的比賽模式拿到前 3 名」或「累積經驗」，依清單順序解鎖。
- 雪場收集章：自由滑行的雪道章（§17.8）；集滿一個雪場所有雪道得到該雪場的稱號。

### 20.4 S3 主人與好感度

- 好感度 0～100（每隻狗分開）：每場比賽 +2、照顧（餵食 10 狗幣、梳毛每天 1 次免費、溫泉 §20.9）各 +5。
- 效果：教練模式指令的效果 ×(1＋好感/200)、興奮度累積 ×(1＋好感/400)。

### 20.5 S4 犬種的主場

| 犬種 | 主場 | 加成 |
|---|---|---|
| 北海道犬、哈士奇、阿拉斯加雪橇犬、薩摩耶 | 北海道的雪場 | 全能力 +2 |
| 秋田犬 | 蔵王（東北） | 全能力 +2 |
| 甲斐犬、紀州犬、四國犬、柴犬 | 長野、新潟的雪場 | 全能力 +2 |

收集章另有「主場犬種限定」版本（用主場犬種拿到時換成特別圖案）。

### 20.6 S5 換裝

- 雪衣、雪鏡、毛帽、狗靴的外觀（不影響數值），在雪場商店用狗幣購買；3D 模型換顏色或加上帽子、靴子幾何。

### 20.7 M7 公園編輯器

- 在 Slopestyle 雪道上放 4～8 個地形（kicker S／M／L、rail、box、roller），位置以 5 m 為單位、側向 ±10 m；不能重疊、間隔 ≥ 40 m。
- 分享碼：`inup1|<resort>|<piste>|<地形清單>`；匯入後可以練習與比分數（本機最佳）。

### 20.8 R2 真實季節

- 依 JST 日期：12～3 月中旬一般季；3 月下旬～4 月春雪機率高；5～11 月「夢之雪」模式（所有雪場開放、雪面帶淡藍色、天氣只有晴）。

### 20.9 R3 溫泉與在地美食

- 溫泉（野沢、蔵王、白馬）：好感度 +5、清除疲勞（P5 新增疲勞：連續比賽 5 場後全能力 −3，溫泉或隔天 JST 清除）。
- 在地美食（每個雪場 1 種，例如野沢菜、成吉思汗烤肉、蔵王的玉蒟蒻）：30 狗幣，下一場比賽某一項能力 +4。

### 20.10 雙板（D5）

- 每隻狗可以選單板或雙板（裝備）。雙板物理差異（暫定）：抓地 ×1.1、轉向 ×1.08、轉體 ×0.85、出發初速 +1 m/s（雪杖）、蹲低減阻 0.5；**不能反腳滑行**（速度在板子後方超過 60°＝摔倒）。
- 3D：兩片細長的板，取代單板。紀錄與成績依雪具分開（`best` 的鍵加上 `/ski`）。

## 21. 第 6 階段規格（RMD 移植準備）

- **對照表**：新增 `tools/inusnow_check/vectors.js`，對每個雪場、每種賽事產生數十組（比賽參數、紀錄）→（狀態、時間或分數、最後位置）的 JSON，給 Go 實作做自動比對。
- **Go 實作範圍**：`terrain`（解碼、模糊、高度、法線、附加物）、`phys`、`core`（旗門、比賽、紀錄）、`slope`、`cross`、`bet`。每個乘法包 `float64(...)`（§11）。
- **伺服器驗證**：上傳（雪場、賽事、`raceSeed`、犬種與能力、裝備、紀錄）→ 伺服器重跑；結果一致才記錄成績。
- **排行榜**：雪場 × 賽事 × 雪質，每週與全期；每日挑戰（R1）。
- **競猜結算**：出賽表、賠率、結果、派彩都在伺服器；狗幣餘額存伺服器。
- **R1 真實雪況**：用氣象廳或 Open-Meteo 的降雪、氣溫決定每天各雪場的雪質與天氣（快取一天）。
- **R4 到現場解鎖**：在雪場 5 km 內定位一次（和約跑 runpo 一樣只用一次、不保存座標）→ 限定收集章或換裝。
- **ADR（在 RMD 寫）**：狗幣不能購買或換成有價物（D10）、資料授權（ODbL、地理院）、雪場與雪道真名的使用（D7）、外部 API 的條款與額度。

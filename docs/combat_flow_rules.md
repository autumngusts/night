## 1. 戦闘の概要

### 前衛と後衛だけの抽象戦闘
本作の戦闘は「エネミーまでの距離」という具体的な位置関係を扱わない、抽象的な戦闘システム。
PC側には「前衛／後衛」という位置関係があるが、エネミー側には前衛／後衛の概念がなく、
1体でも複数体でも「ひとかたまりのデータ」として扱われる。

### 「アクション→ディフェンス」順でターン進行
戦闘中は「ターン」という単位で進行し、1ターンは基本的に「アクションフェイズ→ディフェンス
フェイズ」の順で進む。アクションフェイズ中に「体勢崩し」が発生すると、ディフェンスフェイズの
前に「エクストラフェイズ」が挟まる（詳細は3節）。

### 通常戦闘／簡易戦闘
戦闘の手順そのものには「通常戦闘」と「簡易戦闘」の2種類があり、主にボス戦闘の時間短縮の
ためにアクションフェイズを1度だけ行って終わる「簡易戦闘」が用意されている（詳細は6節）。

### コラム「戦場シートを使うと便利」
戦場シート（398頁）には、①戦場（前衛エリア／後衛エリア）②ダメージ・前衛&後衛・敵視の
決定方法の概要③エネミーのHPを公開・管理する欄④エネミーHPの管理概要、が用意されている。

## 2. 前衛エリア・後衛エリア・敵視

前衛エリアは、エネミーと接敵しているエリア。後衛エリアは、基本的に射撃武器でしか攻撃を
行えず、エネミーからの「乱戦ダメージ」の対象にも含まれない。「敵視」は、エネミーからの
敵対的なアクションの対象になりやすさを表す値で、個別アクションの対象選定に使われる。

### 決定方法
各PCは「アクションフェイズ開始時のスタミナダイス獲得」の際に、前衛／後衛と敵視を
（毎ターン）決定し直す。簡易戦闘（ディフェンスフェイズを行わない）では決定不要。

### エネミー側には前衛/後衛の概念がない
エネミーは前衛/後衛を問わず、基本的に総合ダメージを受ける。

### 前衛エリアと後衛エリアの差（表）

| 比較項目 | 前衛エリア | 後衛エリア |
|---|---|---|
| 近接武器攻撃 | 可 | 不可 |
| 射撃武器攻撃 | 可 | 可 |
| 聖杯瓶使用 | 可 | 可 |
| スキルの使用 | スキル内容による | 可 |
| 消耗品の使用 | 消耗品内容による | 可 |
| エリア移動 | 可→後衛になる | 頭割りで受ける（味方前衛がいれば影響なし） |
| 乱戦ダメージ | 可 | このエリアで復活（≒対象外） |
| 個別ダメージ | 頭割りで受ける | 一部限定 |
| 瀕死状態 | このエリアで受ける | このエリアで復帰 |

> ✗ 表の一部セル（後衛エリアの「乱戦ダメージ」「個別ダメージ」欄）は文字が不鮮明で、
> 正確な文言を再現できていない。既存の`docs/enemy_damage_rules.md`側の実装（乱戦ダメージは
> 前衛のみ対象、後衛は基本的に対象外）と矛盾しない範囲で書いているが、要再確認。

## 3. ターン/フェイズ進行

1ターンは基本的に「アクションフェイズ→ディフェンスフェイズ」の2フェイズで進行する。
アクションフェイズ中に「体勢崩し」が発生すると、ディフェンスフェイズの前に「エクストラ
フェイズ」が挟まる。

| フェイズ | 内容 | 参照頁 |
|---|---|---|
| 戦闘手順1 | アクションフェイズ | 099頁 |
| 戦闘手順EX | エクストラフェイズ（体勢崩し発生時のみ） | 120頁 |
| 戦闘手順2 | ディフェンスフェイズ | 102頁 |
| 戦闘手順3 | エンドフェイズ | 104頁 |

- **アクションフェイズ**：PCが武器攻撃などのアクションを行う。
- **エクストラフェイズ**：体勢崩しが発生した場合のみ、エネミーがボーナス行動権を得て
  再度アクションフェイズ相当の処理が挟まる。
- **ディフェンスフェイズ**：エネミー側の行動（乱戦/個別ダメージ）が発生する。PCはガードや
  回避を行う。
- **エンドフェイズ**：ターン終了の確認。通常戦闘でエネミーを撃破していれば、または簡易
  戦闘でエネミーの現在HPが1以上残っていれば、それぞれの終了処理へ進む。

## 4. 戦闘開始時の公開情報／非公開情報（信頼度やや低）

戦闘開始処理では、GMはプレイヤーに対して「公開情報」を提示する。公開情報には少なくとも
以下が含まれる：
- エネミー名
- 「ザコ戦闘／通常戦闘」のどちらであるか
- エネミーのレベル／レベル補正（最大値／現在値も踏まえた値）
- エネミーの弱点
- 追加ルール（シナリオに記載がある場合）

「非公開情報」（エネミーの詳細な解説・戦闘終了時に明らかになる情報など）は、戦闘を
進めてからでないと明かしてはならない。

> ✗ この節の原文は文字がかすれておりかなり意訳している。公開情報/非公開情報の正確な
> 境界線（具体的にどの項目が非公開か）は物理本で要再確認。

## 5. 戦闘の手順の大枠

戦闘全体は「戦闘前判断→戦闘開始処理→戦闘手順（ターン進行、3節）→戦闘終了処理」の
順で進む。

- **戦闘前判断**（詳細は7節）：フロアの〔描写〕を聞いた段階で、危険を感じたPCがそのフロアの
  イベント（戦闘を含む）を丸ごとスキップ／一時保留できるかどうかの判断。
- **戦闘開始処理**（詳細は8節）：公開情報の開示→ザコ戦闘の判定→インターバル/装備変更、
  の3手順。
- **戦闘手順**：3節のターン進行を、決着がつくまで繰り返す。
- **戦闘終了処理**：エネミー撃破後、「撃破ルーン」を獲得でき、「潜在する力」を獲得できる
  場合もある。

## 6. 通常戦闘・簡易戦闘・ボス戦闘・ザコ戦闘（信頼度低）

> ✗ この節は原文がかなり不鮮明で、文意が通らない箇所が多かった。以下は要旨としての
> 再構成であり、細部の正確性は低い。実装前に必ず物理本を確認すること。

本作には直交する2つの分類軸がある：
1. **手順としての「通常戦闘」／「簡易戦闘」**：通常戦闘はエネミーのHPが0になるまでターンを
   繰り返す。簡易戦闘は基本的にアクションフェイズを1回（体勢崩しが起きればエクストラ
   フェイズも）行うだけで終わる、主にボス戦闘の時間短縮のための簡略ルール。
2. **シナリオ上のイベント分類としての「ボス戦闘」／「ザコ戦闘」**：シナリオ側であらかじめ
   「ボス戦闘」または「ザコ戦闘」に指定されている。目安として、エネミーのレベルがPCの
   平均レベルより高ければボス戦闘寄り、低ければザコ戦闘寄りになる（✗正確な判定式・
   L補の扱いは原文から再現できず）。

コラム「L補を考慮」：GMがエネミーのレベル・レベル補正（L補）をPCへ伝える際は、開始装備の
補正なども含めた最終値を伝える必要がある、という趣旨の記載があった（✗詳細な計算式は
不鮮明で再現できず）。

## 7. 戦闘前判断（信頼度やや低）

PCはフロアの冒頭〔描写〕を聞いた段階で、そのフロアの戦闘を含むイベントを避けたい場合、
「突破判定」を行うことで、そのフロアのイベントを一時保留・スキップできる（`docs/
scenario_flow_rules.md`4節の「フロアのスキップ」と同じ仕組みの模様）。

**突破判定のデメリット**：突破判定に失敗すると「タイムロス」が発生する。成功した場合も、
戦闘やイベントを完全に無かったことにはできない（スキップした内容は後で再度訪れた際に
残り続ける）、という趣旨の記載があった。

> ✗ 「突破判定に成功した場合と失敗した場合、それぞれ具体的に何が起こるか」の対応関係は
> 原文がかなり不鮮明で正確に再現できていない。`docs/scenario_flow_rules.md`4節と内容が
> 重複・類似している可能性が高く、実装時はそちらを優先して参照すること。

## 8. 戦闘開始処理（信頼度やや低）

シナリオで戦闘の発生が示された場合、以下の3手順で戦闘を開始する。

| 手順 | 内容 |
|---|---|
| 〔手順1〕 | 公開情報の開示（4節参照） |
| 〔手順2〕 | 「ザコ戦闘」の判定（6節参照、PCの平均レベルとエネミーのレベルを比較） |
| 〔手順3〕 | 戦闘開始時「インターバル／装備変更」 |

**インターバルと回復禁止**：戦闘開始処理では、シナリオに特に指示がない限り「インターバル」
（9節）が発生し、聖杯瓶使用や祈祷/スキル使用が行える。ただし、シナリオ側に「回復する間も
なく戦闘する」等の指示がある場合は、このインターバルが発生しない。

**装備変更の宣言**：戦闘開始処理で公開されたエネミーの弱点等を踏まえ、PCはこのタイミングで
装備変更を宣言できる。

## 9. インターバルと戦闘終了処理

### インターバル
「インターバル」は、PCが比較的落ち着いた状況で身支度を整えられるタイミング。実行可能な
内容：
- 装備品の準備状態／装備状態の変更
- PC同士の装備品・消耗品の受け渡し
- 聖杯瓶使用
- 消耗品使用
- 〔Action〕スキル使用

**発生時期**：`docs/scenario_flow_rules.md`3節・4節の〔2-3-3〕直後インターバル・〔描写〕
直後インターバル、チットイベント「商人」「祝福」直後インターバル、および本ドキュメント
8節の戦闘開始時「インターバル」。

### 戦闘終了処理
エネミーを撃破すると戦闘終了処理を行う。シナリオに示されている「撃破ルーン」を獲得でき、
「潜在する力」を獲得できる場合もある。

## 1. 戦闘の概要

### 前衛と後衛だけの抽象戦闘
本作の戦闘は「エネミーまでの距離」という具体的な位置関係を扱わない、抽象的な戦闘システム。
PC側には「前衛／後衛」という位置関係があるが、エネミー側には前衛／後衛の概念がなく、
1体でも複数体でも「ひとかたまりのデータ」として扱われる。

### 「アクション→ディフェンス」順でターン進行
戦闘中は「ターン」という単位で進行し、1ターンは基本的に「アクションフェイズ→ディフェンス
フェイズ」の順で進む。アクションフェイズ中に「体勢崩し」が発生すると、ディフェンスフェイズの
前に「エクストラフェイズ」が挟まる（詳細は3節）。

### 通常戦闘／簡易戦闘
戦闘の手順そのものには「通常戦闘」と「簡易戦闘」の2種類があり、主にボス戦闘の時間短縮の
ためにアクションフェイズを1度だけ行って終わる「簡易戦闘」が用意されている（詳細は6節）。

### コラム「戦場シートを使うと便利」
戦場シート（398頁）には、①戦場（前衛エリア／後衛エリア）②ダメージ・前衛&後衛・敵視の
決定方法の概要③エネミーのHPを公開・管理する欄④エネミーHPの管理概要、が用意されている。

## 2. 前衛エリア・後衛エリア・敵視

前衛エリアは、エネミーと接敵しているエリア。後衛エリアは、基本的に射撃武器でしか攻撃を
行えず、エネミーからの「乱戦ダメージ」の対象にも含まれない。「敵視」は、エネミーからの
敵対的なアクションの対象になりやすさを表す値で、個別アクションの対象選定に使われる。

### 決定方法
各PCは「アクションフェイズ開始時のスタミナダイス獲得」の際に、前衛／後衛と敵視を
（毎ターン）決定し直す。簡易戦闘（ディフェンスフェイズを行わない）では決定不要。

### エネミー側には前衛/後衛の概念がない
エネミーは前衛/後衛を問わず、基本的に総合ダメージを受ける。

### 前衛エリアと後衛エリアの差（表）

| 比較項目 | 前衛エリア | 後衛エリア |
|---|---|---|
| 近接武器攻撃 | 可 | 不可 |
| 射撃武器攻撃 | 可 | 可 |
| 聖杯瓶使用 | 可 | 可 |
| スキルの使用 | スキル内容による | 可 |
| 消耗品の使用 | 消耗品内容による | 可 |
| エリア移動 | 可→後衛になる | 頭割りで受ける（味方前衛がいれば影響なし） |
| 乱戦ダメージ | 可 | このエリアで復活（≒対象外） |
| 個別ダメージ | 頭割りで受ける | 一部限定 |
| 瀕死状態 | このエリアで受ける | このエリアで復帰 |

> ✗ 表の一部セル（後衛エリアの「乱戦ダメージ」「個別ダメージ」欄）は文字が不鮮明で、
> 正確な文言を再現できていない。既存の`docs/enemy_damage_rules.md`側の実装（乱戦ダメージは
> 前衛のみ対象、後衛は基本的に対象外）と矛盾しない範囲で書いているが、要再確認。

## 3. ターン/フェイズ進行

1ターンは基本的に「アクションフェイズ→ディフェンスフェイズ」の2フェイズで進行する。
アクションフェイズ中に「体勢崩し」が発生すると、ディフェンスフェイズの前に「エクストラ
フェイズ」が挟まる。

| フェイズ | 内容 | 参照頁 |
|---|---|---|
| 戦闘手順1 | アクションフェイズ | 099頁 |
| 戦闘手順EX | エクストラフェイズ（体勢崩し発生時のみ） | 120頁 |
| 戦闘手順2 | ディフェンスフェイズ | 102頁 |
| 戦闘手順3 | エンドフェイズ | 104頁 |

- **アクションフェイズ**：PCが武器攻撃などのアクションを行う。
- **エクストラフェイズ**：体勢崩しが発生した場合のみ、エネミーがボーナス行動権を得て
  再度アクションフェイズ相当の処理が挟まる。
- **ディフェンスフェイズ**：エネミー側の行動（乱戦/個別ダメージ）が発生する。PCはガードや
  回避を行う。
- **エンドフェイズ**：ターン終了の確認。通常戦闘でエネミーを撃破していれば、または簡易
  戦闘でエネミーの現在HPが1以上残っていれば、それぞれの終了処理へ進む。

## 4. 戦闘開始時の公開情報／非公開情報

「公開情報」は、GMが「戦闘開始処理」でプレイヤーに公開しておくべきエネミーや戦場の情報。
プレイヤーはこれらの情報を考慮しつつ戦闘を乗り切る必要がある。「非公開情報」は、GMが
プレイヤーに教える必要のない情報で、実際に戦うことで明らかになっていく。

### 公開情報（常時）
- 「ボス戦闘／ザコ戦闘（6節）」のどちらなのか。ザコ戦闘なら、さらに「通常戦闘／簡易戦闘
  （6節）」のどちらになるのか。
- エネミーの「名前／レベル／HP（最大値／現在値）／外見の雰囲気」（レベル補正＝L補も
  ふまえた値）。エネミーの外見は、各エネミーに用意された写真を見せる。
- エネミーの「弱点」。
- 追加ルール（戦闘のシチュエーションごとの特殊処理。シナリオに記載——例：「狭い戦場で、
  全員が自動的に前衛になる」）。これらはあらかじめプレイヤーへ公開しておく。

### 戦闘開始時の非公開情報
- エネミーの「アクション内容／HP価値／ガード回数／属性・状態異常に対する耐性」。
- 戦闘終了処理のイベント（シナリオに記載がある場合）——実際に戦闘が終わってからでなければ
  伝えてはならない。

これらの非公開情報がいつ公開情報に変わるかは、各フェイズの解説やエネミーの扱い方の
ページに個別に示されている。

## 5. 戦闘の手順の大枠

戦闘全体は「戦闘前判断→戦闘開始処理→戦闘手順（ターン進行、3節）→戦闘終了処理」の
順で進む。

- **戦闘前判断**（詳細は7節）：フロアの〔描写〕を聞いた段階で、危険を感じたPCがそのフロアの
  イベント（戦闘を含む）を丸ごとスキップ／一時保留できるかどうかの判断。
- **戦闘開始処理**（詳細は8節）：公開情報の開示→ザコ戦闘の判定→インターバル/装備変更、
  の3手順。
- **戦闘手順**：3節のターン進行を、決着がつくまで繰り返す。
- **戦闘終了処理**：エネミー撃破後、「撃破ルーン」を獲得でき、「潜在する力」を獲得できる
  場合もある。

## 6. 通常戦闘・簡易戦闘・ボス戦闘・ザコ戦闘

本作には直交する2つの分類軸がある。

### ① 手順としての「通常戦闘」／「簡易戦闘」
- **通常戦闘**：エネミーのHPを0にするまでターンを繰り返す戦闘。「アクションフェイズ→
  （体勢崩し時のみエクストラフェイズ）→ディフェンスフェイズ→エンドフェイズ」を、決着が
  つくまで何ターンでも繰り返す。
- **簡易戦闘**：基本的にアクションフェイズ1回（体勢崩しが起きればエクストラフェイズも）
  だけで終了する戦闘。**ディフェンスフェイズが発生しない**のが最大の違い。エネミーの
  現在HPがまだ残っていても、その1ターンで戦闘自体は終了として扱う（規則書原文はやや
  不鮮明だが、「追撃損害」や「潜在する力」の獲得といった代替処理に置き換わる旨の記載）。

### ② シナリオ上のイベント分類としての「ボス戦闘」／「ザコ戦闘」
- **ボス戦闘**：シナリオ上の戦闘分類。強いエネミーとの戦い。**ボス戦闘は必ず通常戦闘**
  になる（簡易戦闘にはならない）。
- **ザコ戦闘**：シナリオ上の戦闘分類。弱いエネミーとの戦い。ザコ戦闘は、PCの平均レベルと
  エネミーのレベル（L補込み、端数切り捨て）を比較し、どちらの手順になるかが決まる：
  - PCの平均レベル ＜ エネミーのレベル → **通常戦闘**
  - PCの平均レベル ≧ エネミーのレベル → **簡易戦闘**

### コラム「L補を考慮」
GMがエネミーのレベルを公開・判断する際は、必ず「L補（レベル補正）」を加えた値を使わ
なければならない（生のレベル値だけで比較しない）。

**L補の数値公式（確認済み）**：L補は盤面9マスの列（`idx % 3`）だけで決まり、
`docs/scenario_flow_rules.md`冒頭「L補について」に詳細がある。1日目は左列+0／中列+1／右列+2、
2日目は左列+5／中列+4／右列+3（`night.js`の`fieldLevelsForDay()`）。自動化GMは
`night_gm_flow.js`の`fieldLevelCorrectionForSlot(slotIndex)`でこの値を取得し、樓層敘述・
強敵決定表いずれの敵人追加でも自動的に加算する。

## 7. 戦闘前判断

「戦闘前判断」は、PCたちがシナリオに沿って戦闘前にできることを表す（基本的には`docs/
scenario_flow_rules.md`＝第5部エクスプロールセクションで解説されている内容と同じ仕組み。
戦闘との関わりが深いため、こちらにも要旨を載せている）。

### 突破判定でフロアごとスキップ可能
PCはGMからフロアの冒頭〔描写〕を聞き終わった時点で、戦闘が起きそうであったり危険が
感じられたりする場合、そのフロアに示されている「突破判定」に挑戦できる。

- **突破判定に成功**：そのフロアで起こる「戦闘を含めたすべてのイベント」を、一時保留して
  スキップできる。そのフロアを無視して先に進んだり、別のフィールドへ移動したりできる
  （**ただし、フロア踏破したことにはならない**）。
- **突破判定に失敗**：「タイムロス」が発生した上で、そのフロアの戦闘をはじめとした
  イベントを進めなければならなくなる（＝スキップできず、しかもペナルティ付きで通常通り
  戦闘に突入する）。

### 突破判定のデメリット（まとめ）
- フロア踏破したことにならない（成功時も）。
- 失敗時にタイムロスが発生する。

### シナリオ内の選択で戦闘を起こさない
上記の突破判定とは別に、シナリオ内の選択肢自体に「そもそも戦闘を起こさない」という
選択肢が用意されていることもある。こうした選択をすることで、事前に戦闘を避けて消耗を
防ぐこともできる。

## 8. 戦闘開始処理

シナリオで戦闘の発生が示された場合、以下の3手順で戦闘を開始する。

| 手順 | 内容 |
|---|---|
| 〔手順1〕 | 公開情報の開示（4節参照） |
| 〔手順2〕 | 「ザコ戦闘」の判定（6節参照、PCの平均レベルとエネミーのレベル＝L補込みを比較） |
| 〔手順3〕 | 戦闘開始時「インターバル／装備変更」 |

### 〔手順1〕公開情報の開示
戦闘開始時には、まずGMが「公開情報」（4節）を示す。PCは公開情報をもとに、その後の
選択を行う。

### 〔手順2〕「ザコ戦闘」の判定
公開情報でその戦闘が「ザコ戦闘」だと明らかになったら、GMはエネミーのレベルとPCの平均
レベル（端数切り捨て）を比較し、そのザコ戦闘が「通常戦闘」になるのか「簡易戦闘」になるのか
をPCたちに伝える（6節の判定式参照）。GMがエネミーのレベルを公開・判断する際は「L補
（レベル補正）」も加えた値を使わなければならない（コラム「L補を考慮」）。

### 〔手順3〕戦闘開始時「インターバル／装備変更」
PCに「インターバル」（9節）の機会が与えられる。

**インターバルと回復禁止**：戦闘開始処理では、シナリオに特に記述がない限り「インターバル」
の手順が発生し、聖杯瓶使用・祈祷/スキルによるHP回復・装備変更などが行える。ただし、
シナリオに「HPを回復する間もなく戦闘する」といった指示がある場合、このインターバルの
処理は行えない。

**装備変更の宣言**：戦闘開始処理を踏まえ、PCは装備変更を宣言できる（例：公開されたエネミーの
弱点に合わせた装備品を選ぶ）。この手順で特に装備変更を宣言しなかったPCは、「開始装備」
（各装備品名の「□開始装備」にあらかじめチェックしておいた装備品）を装備した状態で戦闘を
開始したものとして扱う。

## 9. インターバルと戦闘終了処理

### インターバル
「インターバル」は、PCが比較的落ち着いた状況で身支度を整えられるタイミング。実行可能な
内容：
- 装備品の準備状態／装備状態の変更
- PC同士の装備品・消耗品の受け渡し
- 聖杯瓶使用
- 消耗品使用
- 〔Action〕スキル使用

**発生時期**：`docs/scenario_flow_rules.md`3節・4節の〔2-3-3〕直後インターバル・〔描写〕
直後インターバル、チットイベント「商人」「祝福」直後インターバル、および本ドキュメント
8節の戦闘開始時「インターバル」。

### 戦闘終了処理
エネミーを撃破すると戦闘終了処理を行う。シナリオに示されている「撃破ルーン」を獲得でき、
「潜在する力」を獲得できる場合もある。
